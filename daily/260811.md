## 오늘 배운 것
- 모델 점수는 혼자 보면 의미가 없고, **baseline**과 비교해야 한다. 회귀에서는 train 평균을 계속 예측하는 모델이 기준선이다.
- Diabetes 회귀: Linear Regression RMSE 49.15 vs 평균 baseline 76.16. R² 0.581은 validation 변동의 약 58%를 설명한다는 뜻이다.
- 분류는 Accuracy 하나로 보면 안 된다. 악성 종양을 놓치는 비용이 크면 **Recall**을 같이 봐야 한다.
- ROC-AUC와 AP는 0/1 예측이 아니라 **연속 확률**로 계산한다(순위 능력을 보는 지표).
- 임계값(threshold)은 모델이 배우는 값이 아니라 점수를 행동으로 바꾸는 **정책**이다. "validation Recall ≥ 0.90 중 F1 최고"로 골랐다.
- train / validation / test = 60 / 20 / 20, 분류는 `stratify`, 원본 인덱스 교집합으로 split 중복을 검사했다.
- 전처리(`StandardScaler`)는 train에서만 `fit`하고 validation·test에는 `transform`만 한다. `Pipeline`으로 묶으면 이 경계가 지켜진다.

## 왜 중요한가
- test 결과를 보고 모델이나 임계값을 다시 고르면 test가 선택 과정에 들어가서 최종 평가가 독립적이지 않게 된다.
- "모델과 임계값은 validation에서 끝내고, test는 마지막에 한 번"은 이후 딥러닝·RAG 평가(8장 dev/test)까지 계속 나오는 원칙이다.

## 코드/예시
```python
# Recall 정책을 만족하는 임계값 중 F1이 가장 높은 것을 고른다
def choose_threshold(y_true, probability, minimum_recall=0.90):
    rows = []
    for threshold in np.linspace(0.05, 0.95, 91):
        prediction = (probability >= threshold).astype(int)
        rows.append({
            "threshold": threshold,
            "precision": precision_score(y_true, prediction, zero_division=0),
            "recall": recall_score(y_true, prediction, zero_division=0),
            "f1": f1_score(y_true, prediction, zero_division=0),
        })
    table = pd.DataFrame(rows)
    eligible = table.loc[table["recall"] >= minimum_recall].copy()
    if eligible.empty:
        raise RuntimeError("Recall 정책을 만족하는 임계값이 없습니다.")
    selection = eligible.sort_values(
        ["f1", "precision", "threshold"], ascending=[False, False, False]
    ).iloc[0]
    return selection, table
```
- 결과: test AP 0.9920 · Precision 0.9756 · Recall 0.9524 · F1 0.9639 (임계값과 모델을 고정한 뒤 한 번만 평가)

## 헷갈렸던 부분 & 해결
- Accuracy 0.9737이면 충분히 좋은 것 아닌가 했는데, Recall 0.9302라 악성 일부를 놓친다. 문제의 비용에 맞는 지표를 먼저 정해야 한다.
- 동점 임계값이 여러 개일 때 기준이 필요해서 F1 → Precision → threshold 순서로 정렬해 하나로 고정했다.
