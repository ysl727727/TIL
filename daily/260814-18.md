## 오늘 배운 것
- 양성이 드물면 전부 음성으로 찍어도 Accuracy가 높다. 희소 양성 문제는 AP, PR 곡선, FP·FN의 실제 개수를 같이 본다.
- 불균형 처리: class weight(소수 클래스 오류에 가중치) · undersampling(다수 일부 제거) · SMOTE(소수 이웃 사이 합성). **리샘플링은 CV의 train fold 안에서만** 한다.
- CV splitter는 데이터 구조에 맞춰 고른다.

| 데이터 구조 | Splitter |
| --- | --- |
| 독립적인 일반 행 | `KFold` |
| 불균형 분류 | `StratifiedKFold` |
| 같은 사용자·문서가 반복 | `GroupKFold` |
| 시간 순서가 중요 | `TimeSeriesSplit` |

- 누수 종류: 분할 누수 · 전처리 누수 · target 누수 · 미래 누수 · 리샘플링 누수 · 선택 누수(test 보고 다시 고르기).
- 5장: Grid와 Random Search에 **같은 CV 예산**(후보 12 × 4-fold = 48 fit)을 줘서 공정하게 비교했다. 최고 AP와 0.01 이내 후보 중 fold 변동 → 트리 수 → 깊이 순으로 골랐다.
- 전처리 → `RandomOverSampler` → `LogisticRegression`을 하나의 `imblearn` Pipeline으로 묶고, Pipeline 전체를 `GridSearchCV`에 넣었다.
- artifact에 모델뿐 아니라 feature 순서, dtype, 값 범위, 허용 범주, null 정책을 저장하고 입력 오류 10종을 모델 실행 전에 막았다.

## 왜 중요한가
- `StratifiedKFold`는 클래스 비율만 맞춰 줄 뿐, 같은 원문의 chunk가 train·validation에 같이 들어가는 group 누수는 못 막는다. 나중에 RAG 평가에서 dev/test 근거 문서를 겹치지 않게 나눈 것과 같은 이야기다.
- 저장 → reload 후 점수와 예측이 같은지 확인해야 운영에 올릴 수 있다.

## 코드/예시
```python
def build_review_pipeline():
    numeric_pipeline = Pipeline([
        ("imputer", SimpleImputer(strategy="median")),
        ("scaler", StandardScaler()),
    ])
    categorical_pipeline = Pipeline([
        ("imputer", SimpleImputer(strategy="most_frequent")),
        ("onehot", OneHotEncoder(handle_unknown="ignore")),
    ])
    ...

search = GridSearchCV(
    estimator=pipeline,
    param_grid={"classifier__C": [0.1, 1.0, 10.0]},
    scoring="average_precision",
    cv=StratifiedKFold(n_splits=4, shuffle=True, random_state=RANDOM_STATE),
    refit=True,
)
search.fit(X_dev, y_dev)   # 후보 선택에는 개발 데이터만
```
- 결과: Best C 1.0 · CV AP 0.440 · sealed Test AP 0.631 · reload 점수·예측 일치 `True`

## 헷갈렸던 부분 & 해결
- Pipeline에 sampler가 있는데 예측할 땐 왜 실행되지 않지? → 학습 경로에서만 `fit_resample`로 소수 클래스를 보완하고, 예측 경로에서는 학습된 전처리와 classifier만 쓴다. 그래서 새 요청 3행은 예측도 3행.
- `StratifiedKFold`가 따로 도는 게 아니라 `GridSearchCV`가 fold마다 Pipeline을 반복 학습시키는 구조였다.
- 5-2 심화(artifact, `validate_input`)는 줄마다 역할은 이해되지만 처음부터 혼자 설계하기는 아직 어렵다.
