# 2026-08-19 TIL

> 딥러닝 기초 1장 · 2장 앞부분 (1-2 ~ 2-2) · 학습 흐름, Tensor dtype·shape, broadcasting

## 오늘 배운 것
- 방법 고르기: 공식이 명확하면 규칙 기반 → 구조화된 특징+라벨이 있으면 머신러닝 baseline → 텍스트·이미지처럼 특징을 다 정하기 어렵고 라벨이 충분하면 딥러닝. **딥러닝이 가능하다 ≠ 먼저 써야 한다.**
- 학습 한 바퀴: `batch 꺼내기 → model(x) → loss → zero_grad() → backward() → step() → validation`.
  - `zero_grad()` 이전 gradient 초기화, `backward()` gradient 계산, `step()` parameter 갱신
- 문제 유형마다 출력·Loss·target이 한 묶음이다.

| 문제 | 출력 | Loss | target |
| --- | --- | --- | --- |
| 회귀 | `[B, 1]` | `MSELoss` | float |
| 이진 분류 | `[B, 1]` logits | `BCEWithLogitsLoss` | 0/1 float |
| 다중 분류 | `[B, C]` logits | `CrossEntropyLoss` | class index `int64` |

- Tensor를 만나면 `shape`, `dtype`, `ndim`, `device`부터 찍는다.
- `unsqueeze(0)`은 맨 앞에 batch 차원 추가. `[4, 3] + [3]`은 `[3]`이 행마다 반복돼 `[4, 3]`.
- `pred=[4, 1]`, `target=[4]`를 그대로 연산하면 의도치 않은 broadcasting이 일어난다 → Loss 전에 shape 비교.

## 왜 중요한가
- 학습 코드를 위에서 아래로 읽는 순서와 shape·dtype부터 확인하는 디버깅 순서가 연결됐다. 이후 모든 PyTorch 실습의 기본이다.

## 코드/예시
```python
# zip: 같은 위치끼리 짝지어 반복
for block, stage in zip(code_blocks, stage_names):
    print(block, stage)

# *case: 튜플을 풀어서 위치 인자로 전달
cases = [(False, 400, True), (True, 28000, False)]
for case in cases:
    recommend_start(*case)   # recommend_start(case[0], case[1], case[2])
```
- `.long()`, `torch.int64`, `.to(torch.int64)`는 모두 다중 분류 target을 64-bit 정수 class index로 맞추는 표현이다.

## 헷갈렸던 부분 & 해결
- `for case in cases:`의 `case`가 함수 매개변수인 줄 알았는데, 반복에서 꺼낸 튜플 변수였다. `*`가 튜플을 풀어 준다.
- 함수 정의의 `def func(*args):`는 반대로 여러 인자를 튜플로 **모으는** 동작이다.
