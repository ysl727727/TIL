> 딥러닝 기초 2-3 ~ 3-5 · device, shape·dtype·device 디버깅, 퍼셉트론과 MLP

## 오늘 배운 것
- 모델과 입력 Tensor가 다른 device에 있으면 연산이 안 된다. 모델은 한 번 옮기고, batch마다 입력과 target을 같은 device로 옮긴다.
- 오류 디버깅 순서: 마지막 줄 확인 → shape/dtype/device 중 무엇인지 분류 → 직전 Tensor 정보 출력 → 모델·loss가 기대하는 조건과 비교 → 수정 후 재확인.
  - `nn.Linear` 입력의 마지막 차원 = `in_features`
  - 샘플 하나 `[F]`는 `unsqueeze(0)`로 `[1, F]`
  - `CrossEntropyLoss` target은 `torch.int64`
- 퍼셉트론은 `z = x @ w + b`로 logit 하나를 만든다. 직선 하나로는 XOR을 못 나눠서 MLP는 Linear 사이에 ReLU 같은 비선형 함수를 넣는다.
- `nn.Linear(in, out)`: weight `[out, in]`, bias `[out]`, 출력 `X @ weight.T + bias`.
- 이미지 `[B, C, H, W]`는 `torch.flatten(images, start_dim=1)`로 `[B, C*H*W]`. batch 축은 남긴다.

## 왜 중요한가
- dtype·shape뿐 아니라 **device도 연산 전에 맞춰야 하는 Tensor의 계약**이다. 오류가 길어도 마지막 줄에서 종류를 나누면 볼 범위가 줄어든다.
- flatten은 이미지의 가로·세로 이웃 관계를 긴 벡터로 바꿔 버린다 → 공간 구조를 지키는 CNN이 왜 필요한지로 이어진다.

## 코드/예시
```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = model.to(device)
x, y = x.to(device), y.to(device)

class TinyMLP(nn.Module):
    def __init__(self, input_dim, hidden_dim, output_dim):
        super().__init__()
        self.fc1 = nn.Linear(input_dim, hidden_dim)
        self.relu = nn.ReLU()
        self.fc2 = nn.Linear(hidden_dim, output_dim)

    def forward(self, x):
        x = self.fc1(x)
        x = self.relu(x)
        return self.fc2(x)

total_params = sum(p.numel() for p in model.parameters())

# 조건에 맞는 첫 항목, 없으면 None
first_cuda_run = next((run for run in runs if run["device"] == "cuda:0"), None)
```

## 헷갈렸던 부분 & 해결
- `self`가 입력 데이터인 줄 헷갈렸는데, 만들어진 **모델 객체 자신**이다. `__init__`은 layer 준비, `forward`는 통과 순서, `model(x)`가 `forward(x)`를 실행한다.
- `next(generator, None)`의 두 번째 인자는 조건에 맞는 게 없을 때 `StopIteration` 대신 돌려줄 기본값이다.
- `class`, `self`, `__init__` 같은 클래스 문법을 더 공부해야겠다고 느꼈다.
