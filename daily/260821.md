## 오늘 배운 것
- 활성화 함수 없이 Linear만 쌓으면 결국 **하나의 Linear로 합쳐진다**. 중간에 ReLU를 넣어야 공간을 꺾어서 XOR 같은 패턴을 표현할 수 있다.
- `ReLU(x) = max(0, x)`. shape는 그대로, 값만 바뀐다. 음수 구간 gradient가 0이라 Dead ReLU가 생길 수 있다.

| 함수 | 동작 | 메모 |
| --- | --- | --- |
| ReLU | 음수 0, 양수 유지 | 빠르지만 Dead ReLU |
| LeakyReLU | 음수에도 작은 기울기 | Dead ReLU 완화 |
| Tanh | -1~1 | 양 끝에서 기울기 소실 |
| GELU | 부드럽게 조절 | Transformer에서 많이 씀 |

- 이진 분류: logits `[B, 1]`, target `[B, 1]` float32, `BCEWithLogitsLoss`. 내부에서 Sigmoid를 합쳐 처리하니까 **모델 끝에 Sigmoid를 넣지 않는다.** 확률 0.5 = logit 0.0.
- 다중 분류: logits `[B, C]`, target `[B]` long(0 ≤ target < C), `CrossEntropyLoss`. 내부에 log_softmax가 있어서 **Softmax를 넣지 않는다.**
- Softmax는 순서를 안 바꾸니까 class만 필요하면 logits에서 바로 `argmax`.
- `[B, C]`에서 `dim=1`과 `dim=-1`은 둘 다 class 축. `dim=0`에 Softmax를 걸면 샘플끼리 정규화돼서 틀린다.

## 왜 중요한가
- 출력층 활성화는 습관이 아니라 **문제 유형 · logits shape · target shape·dtype · Loss**를 한 묶음으로 설계하는 것이다. Sigmoid·Softmax를 두 번 적용하는 실수를 막는다.

## 코드/예시
```python
criterion = nn.CrossEntropyLoss()        # 설정을 가진 Loss 객체
loss = criterion(logits, target)         # 호출해서 실제 Loss 계산
probs = torch.softmax(logits, dim=-1)
preds = torch.argmax(logits, dim=-1)
assert torch.allclose(probs.sum(dim=-1), torch.ones(probs.shape[0]))

x = torch.linspace(-3, 3, steps=7)                        # 일정 간격 값
expanded = torch.cat([x, nonlinear_feature], dim=1)       # 축으로 이어 붙이기
mask = (target >= 0) & (target < logits.shape[1])         # Tensor 조건은 and 대신 &
```

## 헷갈렸던 부분 & 해결
- `criterion`이 PyTorch 키워드인 줄 알았는데, Loss 객체에 흔히 붙이는 **변수 이름**일 뿐이다.
- Tensor 조건식에 `and`를 쓰면 안 되고 `&`를 쓰고 각 비교식을 괄호로 묶어야 한다.
