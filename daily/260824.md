## 오늘 배운 것
- 학습의 기준 다섯 줄: `zero_grad() → model(inputs) → criterion(...) → backward() → step()` = 이전 gradient 제거 → 예측 → 채점 → 수정 방향 계산 → 실제 수정.
- 손실 함수는 정답/오답이 아니라 **얼마나 벗어났는지를 미분 가능한 숫자**로 만든다. MSE가 제곱하는 건 양·음 오차 상쇄를 막고 큰 오차에 더 큰 벌점을 주려고.
- reduction: `none`(원소별) · `sum` · `mean`(기본). `backward()`에는 scalar가 필요하다. MSE와 Cross Entropy 값은 서로 직접 비교하면 안 된다.
- Loss 이름만 외우지 말고 `문제 유형 → 출력 shape → target shape → target dtype → Loss`를 한 세트로 본다. 다중 레이블은 `[B, L]` multi-hot float + `BCEWithLogitsLoss`.
- SGD: `new = old − lr × gradient`. lr이 너무 작으면 느리고, 너무 크면 진동·발산·`nan`.
- Adam은 1차·2차 모멘트로 parameter별 이동 크기를 보정한다. `(w−2)²`, `w=0`, `lr=0.1` 첫 step에서 SGD는 `w=0.4`, Adam은 약 `w=0.1`.
- `step()`은 parameter를 바꾸지만 `.grad`를 비우지 않는다 → 다음 backward 전에 `zero_grad()`.

## 왜 중요한가
- Loss 계산, gradient 계산, parameter 수정이 **서로 다른 단계**라는 걸 코드로 확인해야, 학습이 "돌아갔다"가 아니라 "제대로 갱신됐다"를 검증할 수 있다.
- 학습률 실험은 데이터·초기값·optimizer·step 수를 고정하고 lr만 바꿔야 공정하다.

loss.backward()
weight_grad = model.weight.grad.detach().clone()
expected = weight_before - lr * weight_grad
optimizer.step()
assert torch.allclose(model.weight.detach().clone(), expected)   # 예상 SGD 갱신 = 실제

## 헷갈렸던 부분 & 해결
- `total_loss += loss`가 왜 메모리 누수? → `loss`는 계산 그래프와 연결된 Tensor라 누적하면 이전 batch 그래프까지 남는다. 기록은 `loss.item()`(Python 숫자), 역전파는 Tensor `loss.backward()`.
- `zip(values, values[1:])`은 한 칸 밀어서 `(이전, 다음)` 쌍을 만든다.
- `next((key for key, passed in audit.items() if not passed), None)`은 첫 실패 원인 하나만 찾는다.
- SGD와 Adam을 비교할 땐 초기 parameter를 똑같이 복사하고 optimizer state를 따로 써야 한다.
