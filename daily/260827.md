> 딥러닝 기초 9장 · 실험 재현성과 Checkpoint

## 오늘 배운 것
- 재현성은 seed 하나로 끝나지 않는다. `random.seed`, `np.random.seed`, `torch.manual_seed`, `torch.cuda.manual_seed_all`, 그리고 `random_split`·`DataLoader`용 `torch.Generator`까지 같이 관리한다.
- 같은 seed라도 PyTorch·CUDA 버전, 장치, 연산 순서가 다르면 결과가 완전히 같지 않을 수 있다 → 실행 환경도 기록한다.
- 기록 3종: `config`(데이터·모델·optimizer·seed·환경) / `metrics`(epoch별 loss·accuracy) / `checkpoint`(model·optimizer·완료 epoch·history).
- `model.state_dict()`는 weight·bias·buffer **값**, `optimizer.state_dict()`는 Adam moving average 같은 내부 상태. 구조가 아니니까 같은 구조의 모델을 먼저 만들고 `load_state_dict()`로 넣는다.
- `last.pt`는 재개용, `best.pt`는 validation 기준 평가·추론용.
- 정확한 재개는 **완료된 epoch 경계**에서만. 중간에 끊겼으면 그 epoch를 처음부터 다시 돈다. 난수 상태와 loader generator 상태까지 복원해야 한다.

## 왜 중요한가
- 실험 하나의 config·metrics·checkpoint·plot을 run directory 하나로 묶어야 나중에 "어떤 조건에서 나온 숫자인지"를 추적할 수 있다. 이후 RAG에서 `run_config`·자료 해시를 결과에 같이 저장하는 것과 같은 생각이다.

## 코드/예시
```python
checkpoint = torch.load(path, map_location="cpu")        # 파일 → dict (GPU 저장분도 CPU로)
model.load_state_dict(checkpoint["model_state"])          # 값을 실제 모델에 주입
optimizer.load_state_dict(checkpoint["optimizer_state"])

with open(path, "w", encoding="utf-8") as file:
    json.dump(config, file, indent=4, ensure_ascii=False)  # 파일 저장 (dumps는 문자열 반환)

def make_exp_dir(root, exp_name, seed):
    path = Path(root) / f"{exp_name}_seed{seed}"
    path.mkdir(parents=True, exist_ok=True)
    return path        # ← 여기서 path = Path(root)로 덮어쓰던 줄을 지웠다
```

## 헷갈렸던 부분 & 해결
- `json.dump` vs `json.dumps`: 끝의 `s`는 string. dump는 파일에 저장, dumps는 JSON 문자열 반환.
- 파일 모드: `w` 덮어쓰기, `a` 이어쓰기, `r` 읽기. config는 `w`, epoch log 누적은 `a`.
- `ensure_ascii=False` + UTF-8이어야 한글이 `\uXXXX`가 아니라 글자로 저장된다.
- `torch.load()`는 읽기만, `load_state_dict()`가 실제 주입. `strict=False`는 누락 key를 숨길 수 있다.
- `Path.unlink()`는 파일 하나, `shutil.rmtree()`는 폴더 전체 삭제.
- `make_exp_dir()`에서 만든 상세 경로를 `Path(root)`로 다시 덮어써서 상위 `runs`가 반환되는 버그가 있었다. 9-3의 `model_State` → `model_state`도 이름을 맞췄다.
