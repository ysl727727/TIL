## 오늘 배운 것
- 첫 `Conv2d`의 `in_channels`는 데이터가 정한다(grayscale 1, RGB 3). `out_channels`·`kernel_size`는 설계값이고, 앞 층 `out_channels` = 다음 층 `in_channels`.
- 출력 크기 = `(입력 − kernel + 2×padding) / stride + 1`. `padding = kernel_size // 2`면 크기 유지(same padding).
- 공간은 줄이고(pooling·stride) 채널은 늘린다 → 계산량 감소, receptive field 확장, 더 다양한 특징.
- MLP는 완전연결이라 입력 크기에 비례해 parameter가 폭증하고, CNN은 지역 연결 + 가중치 공유라 이미지 크기와 무관하게 고정된다.
- Tensor 메모리 = `numel() × element_size()`.
- RNN: 입력 `[batch, seq_len, input_size]` → `output [batch, seq_len, hidden]`(모든 시점), `h_n [num_layers, batch, hidden]`(마지막 시점). 단층이면 `output[:, -1, :]` = `h_n[-1]` 값까지 같다.
- `seq_len`은 데이터가 정하고 `hidden_size`는 사람이 정하는 값이라 서로 독립이다.
- tanh를 반복할수록 시작 Tensor의 gradient가 작아진다(경사 소실). sigmoid 미분 최대 0.25, ReLU는 양수 구간 1.
- 전체 gradient 크기 = `sqrt(sum(grad ** 2))`(global L2 norm), `clip_grad_norm_`으로 update 크기를 제한한다.

## 왜 중요한가
- dummy 입력을 한 번 통과시켜 classifier `in_features`를 자동 계산하면 이미지 크기가 바뀌어도 Linear mismatch가 안 난다.
- one-step loss는 초기화 영향이 커서 모델 선택 기준이 아니다. MLP vs CNN은 같은 seed·같은 DataLoader generator·같은 validation metric으로 비교해야 한다.

## 헷갈렸던 부분 & 해결
- 12-4에서 정의 안 된 `loss_value`를 `round(loss_value, 4)`에 써서 `NameError` → `loss.item()`으로 고쳐야 한다(재실행 대기).
- `with torch.no_grad:`처럼 괄호를 빼면 context manager가 아니라 함수 객체라 실행이 안 된다.
- `/`는 실수 나눗셈, `//`는 몫(내림). `-7 // 2 = -4`.
- `requires_grad`, `ones_like`, `atol`(allclose 절대 허용 오차) 같은 기초 표기를 다시 정리했다.
- `batch_first=False`면 입력을 `[seq_len, batch, input_size]`로 permute해야 한다.
