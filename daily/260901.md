## 오늘 배운 것
- 수동 RNN: `hidden = tanh(token @ W_x + hidden @ W_h)`. 이전 hidden을 다음 시점에 다시 쓰는 게 순차 의존성의 실체다. 첫 token만 바꿔도 마지막 상태가 달라진다.
- 경로 길이: RNN은 `length − 1`, Self-Attention 한 층은 `1`. 대신 attention score 원소 수는 `length²`. 길이가 32배면 score는 1,024배.
- 분류와 생성은 tokenizer만 공유한다.

| | Classification | Generation |
| --- | --- | --- |
| Model | `AutoModelForSequenceClassification` | `AutoModelForCausalLM` |
| Logits | `[B, C]` | `[B, L, V]` |
| Metric | accuracy, macro-F1 | 품질 검토, latency |

- 원본 행 감사: 필수 key 누락, 공백 text, 중복 ID, 허용 안 된 label을 각각 index 목록에 모은다. 오류가 있어도 멈추지 않고 전부 검사해서 report 하나로.
- toy subword tokenizer(greedy longest-match): 시작 위치마다 가장 긴 등록 조각부터, 중간 조각에는 `##`, 끝까지 못 쪼개면 단어 전체를 `[UNK]`. 앞뒤에 `[CLS]`/`[SEP]`.

## 왜 중요한가
- "경로가 짧다"가 "계산량이 작다"는 뜻이 아니다. 직렬 경로 길이와 `L²` 메모리 비용이라는 **서로 다른 병목**을 같이 봐야 한 구조가 무조건 우월하다고 단정하지 않는다.
- 데이터 오류는 토큰화 전에 원본 행 단계에서 잡아야 한다.

## 코드/예시
```python
# Counter 하나로 누락과 중복을 같이 계산
counts = Counter(stages)
missing = [s for s in REQUIRED if counts[s] == 0]
duplicates = [s for s, n in counts.items() if n > 1]
# 순서 오류: 실제 목록을 필수 단계에 투영한 뒤 기준 순서와 비교
projected = [s for s in stages if s in REQUIRED]
```

## 헷갈렸던 부분 & 해결
- `set(stages) == set(REQUIRED)`만 비교하면 중복과 순서를 놓친다 → 투영(projection) 후 순서 비교.
- `if row["text"]`로는 `"  "` 같은 공백 문자열을 못 거른다 → `.strip()`까지.
- 같은 tokenizer API를 쓴다고 model head까지 바꿔 쓸 수 있는 게 아니다. head·loss·후처리·지표가 task마다 다르다.
