> 딥러닝 심화 1장 심화 · 2장 완료(2-2·2-3, 심화) · 3장 Attention 이론

## 오늘 배운 것
- 실험 설정 식별자: `sort_keys=True` + `separators=(",", ":")`로 canonical JSON → SHA-256 hash. key 순서만 바뀌면 같은 hash, `seed`가 바뀌면 다른 hash.
- baseline 추천: 긴 문맥이나 병렬 학습이 중요하면 Transformer, 아니고 streaming이면 RNN/LSTM, 둘 다 아니면 "비교 필요". 실제 benchmark를 대신하지는 못한다.
- `tokenizer.tokenize()`는 특수 토큰 없이, `encode(add_special_tokens=True)`는 `[CLS] … [SEP]`까지 붙인 모델 입력용 ID.
- 동적 padding 두 가지: `tokenizer(texts, padding=True)`는 즉시, `DataCollatorWithPadding`은 개별 토큰화 후 batch를 만들 때 그 batch 최장 길이로.
- 큰 vocabulary는 token 수·UNK를 줄이지만 embedding parameter(`len(vocab) × dim`)가 늘어난다 → 무조건 좋지 않다.
- `offset_mapping`(fast tokenizer만)으로 subword가 원문 몇 번째 글자에서 왔는지 추적한다.
- Attention 이론: `softmax(QKᵀ/√d_k + M)V`, 순서는 **scale → mask → softmax → weighted sum** 고정.
  - `Q=K=V=X`는 값이 같다는 게 아니라 입력 출처가 같다는 뜻
  - mask는 softmax **전에**. 나중에 0을 곱하면 행 합이 1이 안 된다
  - Padding mask `[B, L_k]`(샘플마다 다름) vs Causal mask `[L_q, L_k]`(`torch.tril()`)

## 왜 중요한가
- PAD 위치와 `attention_mask == 0` 위치가 정확히 같아야 모델이 padding을 무시한다. shape를 하드코딩하지 않고 직접 검사했다.
- train/validation/test에 같은 전처리를 `Dataset.map()`으로 적용하고, split id 교집합이 비었는지 집합 연산으로 확인 → 누수 없음.

## 코드/예시
```python
canonical = json.dumps(config, sort_keys=True, ensure_ascii=False, separators=(",", ":"))
config_hash = hashlib.sha256(canonical.encode("utf-8")).hexdigest()[:12]

def tokenize_batch(batch):
    encoded = tokenizer(batch["text"], padding=False, truncation=True, max_length=max_length)
    encoded["labels"] = [int(label) for label in batch["label"]]
    return encoded
tokenized = dataset.map(tokenize_batch, batched=True)

assert torch.equal(input_ids.eq(tokenizer.pad_token_id), attention_mask.eq(0))
```

## 헷갈렸던 부분 & 해결
- `Map: 100% ... N/N` 진행바가 에러인 줄 알았는데 정상 완료 표시였다.
- `split_heads`는 `view + transpose`, `merge_heads`는 `transpose + contiguous + reshape`. `transpose` 뒤에는 메모리 순서가 바뀌어서 `contiguous()` 없이 `reshape`하면 불안전하다.
- `W_O`는 head별 결과를 실제로 섞는 유일한 지점이다(Multi-Head일 때 merge 직후).
- `max_length`는 truncation 없이 원래 길이를 먼저 재고, 절단률이 가장 낮은 후보(동률이면 작은 쪽)를 고른다.
