## 오늘 배운 것
- 언어모델은 문장을 "이해"한다기보다 토큰·문맥의 통계적 패턴을 parameter에 학습한 것이다. 사실을 정확히 외우는 게 아니다.
- 사전학습(대규모 비라벨 텍스트로 일반 패턴) → Fine-tuning·Task Head·Prompt로 목적에 맞게 쓴다.
- LM Objective는 "사전학습 중 반복해서 푸는 문제"이고, 구조(정보가 흐르는 방식)와는 별개다. `BERT = Encoder-only + Masked LM`, `GPT = Decoder-only + Causal LM`.

| | Masked LM | Causal LM |
| --- | --- | --- |
| 질문 | 가려진 토큰은? | 다음 토큰은? |
| 문맥 | 왼쪽 + 오른쪽 | 왼쪽 + 현재 |
| 출발점 | 분류·토큰 이해 | 생성·대화 |

- BERT MLM은 15%를 골라 80% `[MASK]`, 10% 임의 토큰, 10% 그대로. loss는 고른 위치만.
- GPT는 한 칸 shift해서 다음 토큰을 예측한다. 학습은 causal mask로 병렬(Teacher Forcing), 생성은 한 토큰씩 순차.
- Hub = weight + `config.json` + tokenizer + Model Card + 버전. `main`은 움직이는 버전이라 재현성이 필요하면 commit hash로 고정.
- AutoClass는 `config.json`의 `model_type`으로 클래스를 자동 선택한다. Base `AutoModel`은 `last_hidden_state [B, L, H]`만 주고 `logits`가 없는 게 정상이다.

## 왜 중요한가
- Model Card는 task/language → Base인지 Fine-tuned인지 → intended use → 학습·평가 데이터 → limitations → license 순서로 읽는다. license가 있다고 성능·편향·개인정보 문제가 해결되는 건 아니라 내부 평가가 필요하다.
- 모델 weight만 저장하면 안 된다. tokenizer 규칙이 다르면 같은 문장도 다른 `input_ids`가 된다 → 모델과 tokenizer를 한 폴더에 한 쌍으로.

## 코드/예시
```text
Masked Mean Pooling
sum(hidden × mask) / clamp(sum(mask), min=1e-9)     ← padding은 0이 곱해져 빠짐

저장 → 재로드 검증
baseline logits .clone() → save_pretrained (model + tokenizer)
→ 객체 삭제 → from_pretrained(local_files_only=True)
→ torch.testing.assert_close(logits) · torch.equal(pred)
```
- 실습 노트북은 아직 없다(주말로 이월).

## 헷갈렸던 부분 & 해결
- Objective와 Loss는 같은 말인가? → Objective는 풀도록 만든 문제, Loss는 예측과 정답 차이를 숫자로 만든 것. 연결돼 있지만 다르다.
- Causal mask(미래 차단)와 loss mask(`labels=-100`, 어느 위치를 학습할지)는 이름은 비슷하지만 역할이 다르다.
- `AutoConfig`로 weight를 안 불러오고도 `num_attention_heads`, `num_key_value_heads`를 먼저 볼 수 있다 → 3장 MHA/GQA와 연결.
