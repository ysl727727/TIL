> 딥러닝 심화 6장 · Trainer로 하는 텍스트 분류 Fine-tuning (이론 + 7-1 실습) / 종합 과제 2개 제출

## 오늘 배운 것
- Fine-tuning 전에 문제부터 정의한다: 무엇을 입력으로 받고, 어떤 라벨을 예측하고, 무엇을 성공으로 볼지.
- 7-1 데이터 점검: 공백 정규화 → 빈 문장·허용 안 된 label·정규화 후 중복 제거 → `Counter`로 label 분포와 imbalance ratio(`max/min`) → train/validation **leakage** 탐지(정확 중복 + 단어 집합 Jaccard ≥ 0.8 near-duplicate).
- `DatasetDict`: train(갱신) · validation(조정) · test(최종). `id2label`/`label2id`를 `label_mapping.json`으로 저장. split은 `seed` + `stratify_by_column`.
- `Dataset.map(batched=True)`로 토큰화하고 padding은 `DataCollatorWithPadding`이 batch 단위로(동적 padding).
- 불균형이면 Accuracy는 왜곡된다. Macro-F1은 클래스별 F1을 같은 비중으로 평균해서 소수 클래스를 반영한다.
- `TrainingArguments`는 실험 기록 문서다. `Trainer` = model · args · datasets · tokenizer · data_collator · compute_metrics.
- Checkpoint(중간) / Best Model(`load_best_model_at_end`) / Final Model(weight + tokenizer + label_mapping + run_config)은 목적이 다르다.
- Error Analysis: High Confidence Error(잘못 학습·라벨 오류 의심) vs Low Confidence Error(문장 모호·라벨 경계 불명확).

## 왜 중요한가
- validation에 train 문장이 섞이면 일반화가 아니라 **암기 재현**을 재게 된다. 이 생각이 나중에 RAG 평가의 dev ∩ test = `[]`까지 이어진다.
- 극소수 샘플로 일부러 오버핏시켜 보는 sanity check: 이것도 못 외우면 로더·모델·loss에 원초적 버그가 있다.
- 종합 과제 두 개(기초 수학, 딥러닝 기초)를 제출했다. 과제 때문에 이번 주 5·6장 실습은 못 했다.

## 코드/예시
```python
def compute_metrics(eval_pred):
    logits, labels = eval_pred
    preds = np.argmax(logits, axis=-1)
    return {
        "accuracy": accuracy_score(labels, preds),
        "macro_f1": f1_score(labels, preds, average="macro"),
    }
# metric_for_best_model="macro_f1" 이름이 반환 키와 정확히 같아야 한다
```
- 7-1: `" ".join(text.split())`로 공백 정리 후 감사, 정상 record와 오류 report 분리, 자동 검증 통과
- 기초 수학 과제: 문서 임베딩·Cosine 검색 → PCA(고유값 분해) → SVD 저랭크 압축 → Causal Attention forward + softmax/loss + autograd SGD 1 step
- 딥러닝 기초 과제: DataLoader 입구 검사 → MLP·CNN 공정 비교 → best checkpoint 저장·복원·재개 → 최종 test 1회

## 헷갈렸던 부분 & 해결
- validation을 계속 보며 모델을 고치는 것도 간접적인 개입이라, 객관적인 최종 확인에는 따로 test가 필요하다.
- 실행 전 체크: `num_labels` = 데이터 라벨 수, `save_strategy`와 `eval_strategy` 주기 일치, OOM이면 batch size나 `max_length`를 줄인다.
