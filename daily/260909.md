## 오늘 배운 것
- 모델 적응은 바꾸는 대상에 따라 나뉜다. 학습 parameter·비용·위험이 커지는 순서: `Prompt-only → Prompt-tuning → PEFT(LoRA) → Full Fine-tuning`.
  - Prompt Engineering은 사람이 읽는 문장을 고치고, Prompt-tuning은 사람이 못 읽는 soft prompt **벡터**를 학습한다.
- 처음부터 학습하지 않는다. Prompt-only baseline 4요소(평가셋, prompt template, output schema, metric)를 고정하고 오류 분석부터.
- LoRA: `W`를 직접 크게 바꾸는 대신 저랭크 `A`(d×r)·`B`(r×d)를 학습해 `h = Wx + BAx`. 설정은 `r`, `lora_alpha`, `target_modules`, `lora_dropout`.
- Prompt-only vs Fine-tuned 비교는 같은 평가셋·정답·metric·parsing 규칙으로. 평균이 좋아져도 **regression**(전에 맞던 게 틀림)을 따로 본다.
- Forward pass는 logits 한 번, `generate()`는 다음 토큰 선택 → 붙이기를 종료 조건까지 반복.
- `max_length`는 입력+출력 전체, `max_new_tokens`는 새로 만들 토큰 수만.
- Greedy(결정적·안정) vs Sampling(다양) vs Beam(여러 경로 유지). Temperature는 분포의 날카로움, Top-k는 상위 k개, Top-p는 누적 확률 p까지.
- Chat 입력은 `role`/`content` messages다(system · user · assistant). `apply_chat_template()`이 모델별 형식으로 바꿔 주고, `add_generation_prompt=True`가 assistant 답변 시작 자리를 표시한다.

## 왜 중요한가
- 결과표에 `raw_output`과 `prediction`을 같이 남겨야 "정답은 알았는데 형식을 어긴 것"과 "아예 틀린 것"을 구분할 수 있다. prompt template을 바꾸는 것도 실험 조건 변경이라 `PROMPT_VERSION`을 남긴다.
- 생성 결과가 이상하면 decoding 설정보다 **입력부터** 본다: messages → formatted text(`tokenize=False`) → tokenized shape → generate.

## 헷갈렸던 부분 & 해결
- "Prompt-tuning"에 prompt가 들어가서 Prompt Engineering과 같은 건 줄 알았는데, 학습하는 파라미터가 있는 방법이었다.
- QLoRA는 "4-bit 모델 전체를 학습"이 아니라 base weight를 4-bit로 불러오고 LoRA adapter만 학습하는 것.
- adapter만 저장하면 base weight가 없다 → base model ID·revision, PEFT config, tokenizer를 같이 기록.
- 직접 포맷한 문자열에 template을 또 적용하면 특수 토큰이 중복된다 → messages 원본에만 적용.
- decoder-only batch 생성은 마지막 열에서 다음 토큰을 읽어서 left padding을 쓰는 경우가 많다.
