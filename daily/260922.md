## 오늘 배운 것
- 정제는 원본을 덮어쓰지 않고 **별도 산출물**을 만드는 일이다. 3장 원본을 입력으로 받아 새 파일을 만든다.
- 텍스트 정제 순서: `html.unescape()` → `re.sub(r"<[^>]+>", " ", …)` → `" ".join(text.split())`. 순서를 지켜야 이스케이프된 태그와 붙은 문장 문제를 같이 잡는다.
- 정제 코드 1차 검증: `입력 = 정상 + 중복 제외 + 규칙 제외`가 맞는지.
- RAG 문서는 `document_id` / `content` / `metadata` 세 부분으로 고정하고, 출처·날짜를 본문에 섞지 않는다.
- FastAPI는 경로와 함수를 **선언**하고, Uvicorn이 포트를 열어 **실행**한다. 코드에 포트가 없는 이유.
- path(자원 특정) / query(거르기·자르기) / body(구조화 입력). `Query(default=30, ge=5, le=100)`처럼 규칙을 선언하면 `/openapi.json`에 그대로 나온다.
- 422는 형식 위반(함수 들어가기 전, FastAPI가 자동), 404는 형식은 맞는데 자원이 없음(내가 직접 올림).
- Pydantic: `Field(min_length/max_length)`, list 기본값은 `default_factory=list`, `ConfigDict(str_strip_whitespace=True, extra="forbid")`.

## 왜 중요한가
- 제외한 건은 개수만 세지 말고 **왜 제외했는지**도 남겨야 다음에 어디를 고칠지 안다.
- 검증 코드를 함수 밖(스키마)으로 꺼내면 그 자체가 API 문서가 된다.
- `extra="forbid"`가 없으면 오타 키가 조용히 버려지고 200이 나온다. 입력이 틀렸는데 성공하는 게 제일 찾기 어렵다.

## 코드/예시
```text
make_document_id: 허용 문자만 남기고 '-'로 치환 → strip("-") → lower()  → doc-news-001
  (출처가 여럿이면 원본 ID끼리 겹칠 수 있어 출처를 ID에 포함)

@field_validator(..., mode="before")   ← 타입 변환 전, 필드 하나 (아직 문자열일 때 손보기)
@model_validator(mode="after")         ← 전부 채워진 뒤 모델 전체, self를 반환
```
- 4~8장은 강의 교안만 받고 실습 파일이 없어서 이론만 정리했다.

## 헷갈렸던 부분 & 해결
- `strip()`은 앞뒤 공백만 지우고 가운데 연속 공백은 남는다 → `split()` + `join()`.
- 경로에 동사를 넣고 싶어지는 건 대부분 자원 이름을 아직 못 정했을 때다.
- list의 `max_length`는 글자 수가 아니라 **원소 수**.
- 요청 모델과 응답 모델을 분리하고 `response_model`로 응답 필드를 고정한다. 하나로 쓰면 내부 값이 새어 나간다. 등록 충돌은 400이 아니라 409.
- 메모리 저장소 `DOCUMENTS`와 보조 인덱스 `SOURCE_INDEX`는 항상 같이 갱신·초기화해야 한다.
