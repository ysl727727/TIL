## 오늘 배운 것
- 질문 요청에서 `document_id`와 `context` 중 **하나만** 허용한다. 둘 다 오면 무엇을 근거로 답했는지 모르고, 둘 다 없으면 근거 없는 답이 된다 → `model_validator`로 검사(422).
- `resolve_context()`가 (본문, 출처 목록)을 같이 반환하면 응답의 `sources`를 채우는 코드가 한 줄이다. 프롬프트는 지시문 → `[근거]` → `[질문]` → `[답변]` 순서로 경계를 만든다.
- `LLM_MODE`로 mock / external / ollama 전환, **기본값은 mock**. 키는 `Authorization: Bearer` header에만. Ollama 본문은 `data["message"]["content"]`.
- 외부 실패를 우리 API 코드로 바꾼다: 422(계약 위반) / 404(문서 없음) / 502(외부 오류·형식 깨짐) / 503(연결 불가).
- 비동기는 **대기 시간이 겹칠 때만** 빨라진다. `httpx.AsyncClient`를 `async with`로 하나만 만들어 공유. `asyncio.gather()` 결과는 완료 순서가 아니라 **입력 순서**.
- `timeout=2.0`은 connect/read/write/pool **단계별** 최대 시간이다.
- 재시도는 timeout과 5xx만, 4xx(429 포함)는 즉시 실패.
- LLM 실전 10장: 재시도 계층을 겹치면 SDK 3 × 앱 3 × Tool 3 = 최대 27회. retry 책임은 한 계층에만, `OpenAI(max_retries=0)`로 명시. Full Jitter `Uniform(0, min(cap, base × 2^a))`.

## 왜 중요한가
- mock을 "테스트용 임시"가 아니라 **기본 모드**로 두면 키 없이도 전체 경로가 돌아가서 구조 문제를 먼저 잡을 수 있다.
- 외부 오류 코드를 그대로 넘기면 호출자는 우리 API 문제로 오해하고 내부 정보도 샌다.
- 429를 바로 다시 보내면 실패 요청도 한도에 포함돼 더 나빠진다. 데이터 엔지니어링 8장과 LLM 실전 10장이 다른 자리(우리 API / 외부 호출)에서 같은 결론에 도달했다.

## 코드/예시
```text
for attempt in range(2):          ← 최초 1회 + 재시도 1회 = 총 2회 호출
except httpx.TimeoutException     ← RequestError의 하위 클래스라 먼저 잡아야 재시도가 살아 있다
except httpx.RequestError

ExternalServiceError(RuntimeError) → 경계에서 HTTPException(502)
@app.middleware("http") → call_next() 결과를 반드시 return, method·path·status만 기록

fallback ladder: 기본 모델 → 재시도 → 단순 Prompt → 대체 모델 → 캐시·기능 축소 → 사람
```

## 헷갈렸던 부분 & 해결
- `await`를 "비동기 함수 앞에 붙이는 것"으로 외우면 `response.json()`에서 걸린다. 기준은 **기다림이 있는지**다(`response.json()`은 await 대상 아님).
- `except` 순서가 동작을 바꾼다. 하위 클래스를 먼저.
- `range(2)`는 "2번 재시도"가 아니라 "총 2회 호출". 재시도 정책은 최대 호출 횟수로 말하는 게 안전하다.
- middleware에서 `return response`를 빠뜨리면 로그는 남는데 응답이 사라진다.
- Jitter는 "대충 랜덤"이 아니라 여러 client가 같은 순간 다시 몰리는 재시도 폭주를 막는 것이다.
