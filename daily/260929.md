## 오늘 배운 것
- OpenAI SDK 직접 호출은 한 함수가 입력 준비·실행·출력 정리를 다 하고, LangChain은 `Prompt → Model → Parser` 세 역할로 나눈다. 모델이 같으니까 답변 품질이 아니라 **코드 구성 방식**이 다르다.
- `model.invoke()`는 문자열이 아니라 `AIMessage`를 돌려준다. 본문만 쓰려면 Parser를 붙인다. OpenAI의 `user` = LangChain의 `human`.
- 프롬프트가 여러 개거나, 모델·출력 형식을 바꿀 수 있거나, Retriever·Memory를 붙일 계획이면 LangChain, 단발 호출이면 SDK.
- 패키지 역할: `langchain-core`(공통 규격) / `langchain-openai`(어댑터) / `langchain`(상위 기능). 설치 이름은 하이픈, import는 언더스코어.
- `PromptTemplate.format()`은 문자열, `ChatPromptTemplate.format_messages()`는 역할별 메시지 목록. 중괄호를 글자로 남기려면 `{{ }}`.
- Parser는 형식을 **강제하지 않는다**. `get_format_instructions()`를 Prompt에 넣는 단계가 따로 있다. JSON은 자료형 → 키 → 값 순서로 검사.
- Python 드릴: 비교 체이닝, `append`/`extend`·`remove`/`pop`, 리스트 메서드는 제자리 수정이라 `None` 반환.

## 왜 중요한가
- `.env`로 키를 분리하고 `.gitignore`에 `.env`, `.venv/`, `__pycache__/`. 단, `.gitignore`는 이미 올라간 키를 지워 주지 않는다. 노출된 키는 폐기가 유일한 대응이다.
- "LangChain을 쓰니 코드가 길어졌다"는 첫 예제에선 정상이다. 장점은 단계가 늘어날 때 역할과 변경 지점이 나뉜다는 것.
