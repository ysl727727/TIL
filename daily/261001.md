# 2026-10-01 TIL

> LangChain 6-2 ~ 10장 · Retriever, 대화 기억, 관찰, 실패 대응, 통합 Q&A 앱

## 오늘 배운 것
- Retriever는 `str → list[Document]` 계약이다. 0건도 빈 목록이라는 **정상 결과**.
- Prompt에는 문서 목록이 아니라 formatter가 만든 context **문자열**을 넣고, `assign`으로 `documents`도 남겨 출처 확인에 쓴다.
- 모델은 호출마다 기억이 없다. 앱이 `HumanMessage`·`AIMessage`를 session별로 저장했다가 `MessagesPlaceholder`에 **목록**으로 넣는다. 현재 질문은 모델 호출 **후에** 답변과 한 쌍으로 저장.
- 답은 `stream()` 반복문 한 곳에서 출력하고, Callback은 시작·조각·완료·오류를 **관찰만** 한다. 토큰 정보가 없으면 0이 아니라 "제공되지 않음".
- `stop_after_attempt`는 최초 호출 포함 횟수. Retry는 모델 호출 단계에만, 내부 재시도와 곱해지지 않게 `max_retries=0`.
- Fallback은 같은 출력 계약 + `status="degraded"`로 기능 저하를 솔직히 알린다.
- 통합 앱 순서: 검색은 모델보다 먼저, 구조화 검증은 저장보다 먼저. 검색 0건이면 모델을 안 부르고 `not_found`.

## 왜 중요한가
- Parser는 "문자열 목록이다"까지만 확인해서 모델이 `"hr-99"` 같은 출처를 지어내도 통과시킨다. 그래서 앱이 실제 검색 ID와 **다시 대조**해야 한다. RAG 6장 Citation 검사로 그대로 이어지는 생각이다.
- LangGraph는 반복·재개·사람 승인·영속 상태가 필요할 때만 검토한다.

## 코드/예시
```python
# TODO 1: system → history → human
prompt = ChatPromptTemplate.from_messages([
    ("system", "검색 근거 안에서만 답하고 사용한 문서 ID를 sources에 넣으세요.\n{format_instructions}"),
    MessagesPlaceholder(variable_name="history"),
    ("human", "검색 근거:\n{context}\n\n질문: {question}"),
]).partial(format_instructions=parser.get_format_instructions())

# TODO 2: 최근 대화 4개(= 2번) + 근거 + 질문, policy는 한 번만
messages = prompt.invoke({"history": history.messages[-4:], "context": context, "question": question})
result = policy.invoke(messages)

# TODO 3: 출처 검증을 통과한 뒤에만 질문·답변을 같이 저장
allowed = {d.metadata["id"] for d in found}
if not result.sources or not set(result.sources) <= allowed:
    raise ValueError("응답 출처가 실제 검색 결과와 일치하지 않습니다.")
history.add_messages([HumanMessage(content=question), AIMessage(content=result.answer)])
```

| 세션 | 결과 | 저장 후 메시지 수 |
| --- | --- | --- |
| a (2번 질문) | grounded / primary | 4 |
| b (검색 0건) | not_found / local | 기록 없음 |
| c (1번 실패 → Retry) | grounded / primary | 2 |
| d (2번 실패 → Fallback) | degraded / fallback | 0 (빈 기록) |

## 헷갈렸던 부분 & 해결
- `"history": history`(객체)를 넣으면 `ValueError` → `history.messages[-4:]`(목록)를 넣어야 한다. `[:4]`면 오래된 4개가 들어간다.
- 빈 `sources`는 `issubset`을 항상 통과한다(공집합 ⊆ 무엇이든) → `not result.sources`도 따로 막는다.
- c의 route가 primary인 이유: Retry **안에서** Primary가 결과를 만들었으니까.
- `flush()` 완료 ≠ 원격에서 조회 가능.
- 6~10장은 이론이 많아서 10장 통합 실습 TODO 1~3만 했다.
