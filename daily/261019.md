## 오늘 배운 것
- **검색 성공 ≠ 답변 가능.** `호텔비`는 표현이 달라 검색 실패, `개인 취미`는 검색은 됐지만 문서에 답이 없다. 원인이 다르니 대응도 다르다(임베딩 검색 vs "확인 불가" 안내).
- 역색인은 단어 → 문서 ID 집합. OR = 합집합, AND = 교집합.
- 문서 예산 = 한도 − 지시문 − 질문·이력 − 출력 예약 − 여유(8192 → 6000).
- RAG(검색) · Long Context(긴 입력 능력) · CAG(계산 상태 재사용)는 같은 축이 아니다. KV cache는 답변이 아니라 **입력 계산**을 재사용한다.
- 2장: HTML은 태그 삭제보다 본문 범위 선택이 먼저. PDF 줄바꿈은 페이지 폭 때문.
- 현행은 게시일이 아니라 `status`로 고르고, 중복 키(version, category, 본문 해시)로 복사본만 빼고 구버전은 남긴다. 정제는 뜻(금액·부정 표현)을 바꾸지 않는다.
- JSONL은 한 줄에 객체 하나. 본문 줄바꿈은 `\n`(두 글자)로 이스케이프돼서 한 행이 유지된다.

## 왜 중요한가
- **검색 후보와 실제 입력은 다르다.** `retrieve`의 `rows`(후보 3개)와 `build_context`의 `context`/`sources`(예산 260 안에 들어간 2개)를 따로 봐야 하고, 출처는 Context에 **실제로 들어간 것만** 연결한다. RAG 과목 내내 반복된 원칙의 시작.
- 저장에 성공했다고 쓸 수 있는 구조인 건 아니다. 다시 읽어서 문법 오류(JSON으로 못 읽음)와 스키마 오류(읽히지만 약속과 다름)를 행 번호와 함께 나눈다.

## 헷갈렸던 부분 & 해결
- `row =`로 받고 `rows`를 써서 `main.py`에 있던 다른 검색 결과가 쓰였다 → 이름 통일.
- `assert`는 반환 문자열을 글자 하나까지 비교한다(`"전체 입력 + prefix cache 비교"`).
- `== "category"`(글자)가 아니라 `== category`(변수). `.split()`이 아니라 `.strip()`.
- `split(". ")`: `"."`로 나누면 마지막이 빈 문자열이 되고 숫자 속 점에서도 잘린다.
- `enumerate`는 `(번호, 값)`으로 꺼내지만, 함수에 넣을 땐 정의 순서 `inspect_line(line, number)`.
- KV cache를 쓰면 이전 답변이 그대로 나오나? → 아니다. 답변을 그대로 돌려주는 건 응답 캐시.
