> RAG 3일차 · 5장 Vector Store(Qdrant) / 추가 과제: Qdrant Cloud, FAISS

## 오늘 배운 것
- Point = `id + vector + payload`. `uuid5(chunk_id)`라서 같은 청크는 항상 같은 ID → Upsert를 두 번 해도 1개.
- 28개 Upsert 후 current 필터로 Top-3 = 4장 NumPy와 같은 `0.8945 · 0.875 · 0.8444`.
- 필터는 점수를 바꾸지 않고 **후보 자격**만 정한다("8만원인가요?"에서 travel-old 0.9003이 빠짐).
- 다시 청킹하면 청크 ID가 모두 바뀌어서 이전 Point가 남는다 → `old_ids − new_ids` 삭제(3 → 5 → 2).
- ANN은 일부만 탐색해서 놓칠 수 있다(겹침 0.5).
- Qdrant Cloud는 `:memory:`와 달리 데이터가 **남고**, **Strict Mode**라 필터 필드에 `create_payload_index`가 필수다. 결과는 메모리 모드와 같았다.
- FAISS: `IndexFlatIP`(정규화 벡터라 내적 = 코사인)와 `IndexHNSWFlat`(ANN) 모두 같은 Top-3. 벡터만 저장해서 원문은 `chunks[i]`로, 현행 필터는 직접 처리.

## 왜 중요한가
- 글 → Point까지 한 줄로 이어졌다: 청크(`passage:`) → 토크나이저(input_ids + mask) → Lookup Table → Self-Attention 12층 → 풀링(`axis=0`, 384) → 정규화(길이 1) → Point.
- 정규화하면 코사인 분모가 1 × 1 = 1이라 내적만으로 코사인이 된다. 그래서 Collection은 `COSINE`, FAISS는 `IndexFlatIP`.

## 코드/예시
```python
# Qdrant Cloud: :memory: 대신 URL + 키, 필터 필드에 인덱스
client = QdrantClient(url=os.environ["QDRANT_URL"], api_key=os.environ["QDRANT_API_KEY"])
client.create_payload_index(collection, "metadata.status",
                            field_schema=models.PayloadSchemaType.KEYWORD, wait=True)

hits = client.query_points(collection, query=query.tolist(), limit=3,
                           query_filter=current_filter, with_payload=True).points

# FAISS: 벡터만, 원문은 chunks[i], 필터는 직접
index = faiss.IndexFlatIP(vectors.shape[1])
index.add(vectors)
scores, ids = index.search(query.reshape(1, -1).astype("float32"), 6)
```

## 헷갈렸던 부분 & 해결
- `.points`는 왜 붙이지? → `query_points`는 리스트가 아니라 결과 상자(`QueryResponse`)를 준다. `count(col).count`도 같은 모양(`CountResult(count=28)`). Qdrant 결과는 "상자 → 점으로 꺼내기".
- 클래스 = 틀, 객체 = 그 틀로 만든 값. 속성은 `obj.이름`(괄호 없음), 메서드는 `obj.이름()`. `index.collection.count`는 문자열의 count라 틀리고 `index.client.count(index.collection)`이 맞다.
- `vectors`는 `self`에 저장하지 않는다. Upsert한 뒤엔 Qdrant 안에 있다. `model`은 질문 임베딩에 필요해서 저장.
- `.tolist()`: Qdrant는 JSON으로 주고받아서 NumPy 배열을 리스트로 바꿔 보낸다. FAISS는 반대로 `float32` 배열을 받는다.
- `uv run --env-file`에 절대 경로를 쓰면 공백(`RAG 3일차`) 때문에 실패해서 `$env:UV_ENV_FILE = "../../.env"`로 실행했다.
- 5-3 `main.py` 46줄 `print(type)(...)` → `print(type(...))`.
