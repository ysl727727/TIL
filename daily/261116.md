## 오늘 배운 것
- **바꾸는 곳이 다르다.** 프롬프트는 지시, RAG는 근거 문서, 파인튜닝은 가중치. 자주 바뀌는 지식(금액)은 문서로, 지시해도 반복되는 행동(근거 읽기 · JSON · 보류)은 학습으로.
- **입력과 정답을 나눈다.** `cases`(질문 + 문서)만 모델로, `review_criteria`는 사람이 출력과 비교할 때만. 같은 질문에 문서만 다른 over\_limit / updated로 "외운 답인지 읽은 답인지" 가른다.
- **SFT · DPO = 학습 목표, LoRA · QLoRA = 학습 대상.** "LoRA로 SFT를 한다"가 맞는 말.
- **학습은 `p − y` 방향.** 세 점수 예제에서 확률 0.333 → 0.403, 손실 1.099 → 0.909. `backward()`는 기울기만, `step()`이 값을 바꾼다. `cross_entropy`에는 로짓을 넣는다.
- **비교 조건을 고정한다.** revision 커밋 해시 · float32 · greedy · `repetition_penalty` 1.1 · `max_new_tokens` 192를 코드에 명시. 저장소 기본값은 sampling이라 그대로 쓰면 실행마다 답이 달라진다.
- **형식 · 의미 · 참조 일치는 다르다.** 내 결과: 응답 8개 모두 `json_object`에서 실패(앞말 · 코드 펜스 · `answered` 한 단어), simple/updated는 192토큰에서 잘림, 형식 0/4 · 0/4. 의미도 boundary 승인 필요(오답) · missing 50만원(환각) 등 전부 틀림 → 이것이 학습할 행동.
- **통합 실습** TODO 1\~8 통과, 응답 8개가 수업 노트북과 글자까지 같게 재현됨. **직접 구현 Easy** ①\~④ 통과.
- **보강(NumPy).** 배열은 같은 타입 숫자 한 덩어리, 식 한 번이 모든 칸에. `axis=k`는 k번 축을 없애며 계산, `keepdims=True`로 브로드캐스팅 맞추기, softmax는 최댓값을 빼서 오버플로 방지. 기초 1\~3 · 응용 1\~3 통과.

## 왜 중요한가
- 학습 뒤 "좋아졌다"를 말하려면 학습 전 같은 조건의 원문이 있어야 한다. 모델 버전 · 데이터 · 설정 · 원문 네 가지를 같이 남겨야 나중에 무엇 때문에 달라졌는지 답할 수 있다.
- 자동 형식 검사만 보면 "형식은 맞지만 경계 판단이 틀린 답"을 성공으로 센다. 의미는 사람이 읽고, 그 판단을 2장 학습 예시(대조 쌍)로 연결해야 한다.
- 파인튜닝 수식(softmax · `p − y` · 축)은 결국 배열 계산이다. 보강 NumPy가 그 바닥이다.

## 코드/예시
```python
# 통합 실습 TODO 3 — ensure_ascii=False를 빼면 한글이 \uXXXX가 되어 모델이 못 읽는다
return [
    {"role": "system", "content": instruction},
    {"role": "user", "content": json.dumps(model_input, ensure_ascii=False)},
]

# 직접 구현 ③ — 기울기 = 오차(p − y) × 입력, SGD
def train_step(W, x, y, lr):
    x_vec, y_vec = one_hot(x), one_hot(y)
    p = softmax(forward(W, x_vec))
    loss = -math.log(p[y])
    for o in range(V):
        err = p[o] - y_vec[o]
        for i in range(V):
            W[o][i] -= lr * err * x_vec[i]
    return loss
```

```python
# 보강 응용 3 — softmax, 최댓값을 빼도 결과는 같고 오버플로가 없다
def softmax(z):
    z = np.array(z)
    e = np.exp(z - z.max())
    return e / e.sum()
```

## 헷갈렸던 부분 & 해결
- **`softmax(dim=-1)`의 -1.** 후보 토큰이 놓인 마지막 축끼리 합 1. 실제 모델 `[B, T, 151936]`에서도 어휘 축은 항상 마지막이라 `-1`이 같은 코드로 통한다.
- **`.detach().clone()`.** `scores.grad`는 PyTorch가 계속 쓰는 칸이고 `backward()`마다 누적된다. detach는 메모리를 공유해서 원본이 바뀌면 같이 바뀌고, clone까지 해야 그 순간 값이 보관된다.
- **`build_messages`가 리스트인 이유.** 대화는 순서 있는 메시지 여러 개이고, 같은 role이 여러 번 나올 수 있다. 3장에선 끝에 assistant 정답을 `+`로 붙인다.
- **ensure\_ascii 버그.** 빼먹었더니 생성이 "1,900,000,000" · 영어 · `"status":"success"`로 엉망. 자기 점검은 `json.loads` 비교라 통과했다 → 검사 통과 ≠ 모델이 받은 문자열이 맞다. `%pip install` 뒤 런타임 재시작을 안 해서 transformers 5.22.1이 남은 것도 같이 고쳤다.
- **one-hot.** 한 칸만 1인 벡터. `W · one_hot(i)` = W의 i번 열 꺼내기라 학습 때 그 열만 바뀐다. 실제 모델은 임베딩 테이블에서 행을 바로 꺼낸다.
- **"이하 → 승인 필요".** 직접 구현 모델은 앞 토큰 하나만 봐서 `승인` 앞이 이하였는지 몰라 50:50이 최선. 손실 0.37이어도 업무상 오답.
- **보강.** `len(a > t).sum()`은 칸 수 전체(len)라 틀림 → `(a > t).sum()`. 분산은 평균 ÷ 개수가 아니라 편차² 평균. numpy 2.5.5는 스마트 앱 컨트롤이 막아서 버전 고정.
