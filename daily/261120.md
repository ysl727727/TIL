## 큰 흐름
```text
4장:  저랭크 업데이트(4-1) → PEFT 학습(4-2) → 저장 · 복원 · 병합(4-3) → 같은 조건 비교(4-4)
      h = Wx + (α/r)·BAx → B = 0 시작 · lora_만 학습 → 어댑터 몇 MB · 오차 0.0 → baseline · SFT · LoRA
과정: 1 기준 → 2 데이터 72개 → 3 SFT → 4 LoRA → 5 QLoRA → 6 DPO → 7 평가 · API → 8 검증 · 인계
원칙: W는 고정하고 변화량만 배우고, 어댑터만 저장 · 복원 · 병합한 뒤, 조건을 맞춰 숫자와 원문을 함께 읽는다.
```

## 오늘 배운 것
- **SFT는 무엇을 배우나, LoRA는 어느 파라미터로 배우나.** 4장은 3장과 같은 SFT 목표를 같은 공개 기반 모델에서 새로 시작해 A · B만 학습.
- **h = Wx + (α/r)·B(Ax).** W (m, n) · A (r, n) · B (m, r), A를 먼저 곱해서 BA. ΔW = (α/r)·BA는 W와 같은 모양이라 더할 수 있고 rank(ΔW) ≤ r.
- **파라미터 수 = r × (입력 + 출력).** q · v에 r 8이면 24블록 540,672개(0.11%), all-linear면 4,399,104개(0.88%).
- **B = 0에서 시작.** 시작 모델 = 원래 모델, 첫 기울기는 B에만(작은 예제 B 기울기 [−2, 2] · 손실 1.0 → 0.36), 그다음부터 A도 학습.
- **붙인 뒤 검사.** 학습 대상 이름이 전부 `lora_`인지, 학습 전 B = 0 · 학습 뒤 B ≠ 0 · W 그대로인지.
- **어댑터만 저장 · 복원.** `save_pretrained` → 같은 기반 + `PeftModel.from_pretrained(is_trainable=False)` → logits 오차 0.0 · 원문 일치. 병합(`merge_and_unload`)은 수치 확인(6.39e-05)이지 품질 평가가 아님.
- **같은 lr 2e-5에선 LoRA가 안 움직인다.** 슬라이드 0/12, 내 원본 실행 dev 0.9167 → 0.8466. lr 2e-4 + all-linear로 바꾸니 dev 0.0140 · 형식 12/12.
- **3장 보고서 확인.** 내 FP32 전체 SFT는 dev 형식 12/12 · 판단 12/12(슬라이드 BF16 10/12), 최고 메모리 9.23 GiB.

## 왜 중요한가
- 큰 모델일수록 전체 SFT는 기울기 · AdamW 상태 때문에 메모리가 감당이 안 된다. LoRA는 학습 대상을 1% 아래로 줄이고 결과물도 몇 MB 어댑터라 업무별로 바꿔 끼울 수 있다.
- "같은 조건"이라도 그 조건이 한쪽에 맞지 않을 수 있다(SFT용 lr). 비교는 조건 대조 → 한 가지씩 바꾸기 → 원문 읽기 순서로.
- 형식 12/12여도 "한도와 같으므로"처럼 이유가 틀릴 수 있다. 점수와 원문을 같이 읽어야 잘 틀리는 모델을 잡는다.

## 코드/예시
```python
# 4-1 두 경로의 합 = 병합한 W
rank, alpha = 1, 2 #alpha는 보통 r의 2배.
lora_output   = W @ x + (alpha / rank) * (B @ (A @ x))   # [3.0, 0.0]
merged_output = (W + (alpha / rank) * (B @ A)) @ x       # [3.0, 0.0]

# 보강 실습에서 바꾼 두 줄
target_modules="all-linear",   # q_proj · v_proj → 7개 선형층 전부
learning_rate=2e-4,            # 2e-5 → 2e-4
```

|---|---|---|---|

| 4장 보강 (2e-4 · all-linear) | 4,399,104 | 0.9167 → 0.0140 | 12/12 |

## 헷갈렸던 부분 & 해결
- **`A @ x` 모양.** `torch.tensor([2., 1., 1.])`는 `(3,)`이라 열벡터처럼 곱해진다. `[[2., 1., 1.]]`은 `(1, 3)`이라 안 맞음.
- **마지막이 `@`가 아니라 `+`인 이유.** LoRA 경로는 기존 출력에 원소별로 더할 보정값. 1차원끼리 `@`는 내적이라 숫자 하나.
- **B = 0인데 B가 바뀐다?** 초기값과 기울기는 다르다. A 기울기가 0인 건 B의 **값**이 0이라서(내 주석의 "B의 기울기가 0"은 고침).
- **`zero_grad()`는 가중치 초기화가 아니라 기울기 초기화.**
- **α는 학습률인가.** 정확히는 변화량 배율 α/r. 키우면 갱신 효과가 커져 학습률을 올린 것과 비슷하게 움직인다. r 8 → 16이면 α 16 → 32로 배율 유지.
- **`allclose`의 atol · rtol.** |a − b| ≤ atol + rtol·|b|. 둘 다 0.01이면 b = 100에서 1.01까지 허용.
- **보고서 config를 안 고쳤다.** 보강으로 lr · target만 바꾸고 report의 config(2e-5 · q · v)는 그대로라 `lora_report.json`이 실제 설정과 다름 → 5장 전에 고치기.
