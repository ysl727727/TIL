## 오늘 배운 것
- **양자화 = 가까운 대표값의 번호 + scale 저장.** 2비트 예제 [−2.0, −0.9, 0.2, 1.3, 2.0] → scale 2.0 → 번호 [0, 1, 2, 2, 3] → 복원 `scale × codebook[번호]` · 최대 오차 0.633. 메모리가 줄어드는 건 저장할 때.
- **n비트 = 2ⁿ칸.** 2비트 4칸, 4비트 16칸. NF4는 16칸을 0 근처에 촘촘하게(가중치가 종 모양이라).
- **scale 비용.** 64개마다 FP32 scale → 4.5비트, 이중 양자화(scale 8비트 + 256개마다 FP32 기준값) → 4.127비트. 다시 줄이는 건 가중치가 아니라 scale. 계산 땐 scale 먼저 → 가중치 → BF16 곱셈.
- **"4비트 모델"이어도 전부 4비트가 아니다.** 저장 NF4(`uint8` 상자) · 계산 BF16/FP32 · 임베딩 · Norm · A · B는 FP32. bitsandbytes는 Linear 층만 4비트.
- **양자화와 LoRA는 줄이는 곳이 다르다.** 양자화 = 고정 가중치 저장(0.92 → 0.68 GiB), LoRA = 기울기 · AdamW 상태(2.76 → 0.006 GiB).
- **prepare → LoRA 순서.** `prepare_model_for_kbit_training`(얼리기 · FP32 · 재계산) 뒤에 `get_peft_model`. 451 MB → 726 MB, 늘어난 양의 272 MB가 FP32 임베딩.
- **0.5B에선 메모리 이득이 안 보인다.** 슬라이드 LoRA 1.615 GiB · 18.5초 vs QLoRA 1.637 GiB · 25.3초. 단어표 비중 27.6%가 본전선(약 27%)이라. 4B에선 −41%, 14B는 QLoRA만 들어감.
- **복원은 같은 조리법으로.** 같은 revision NF4 + 같은 prepare + `is_trainable=False` → logits atol 1e-4 · 원문 일치.
- **Unsloth는 새 학습법이 아니라 LoRA · QLoRA를 빠르게 돌리는 도구.** `unsloth`를 먼저 import, `prompt` / `completion`이면 −100 마스킹 자동.
- **보강 미분.** 기울기 = Δy/Δx, h를 줄이면 미분값(f'(3) = 6), 중앙 차분 `(f(x+h) − f(x−h)) / (2h)`, 기울기와 **반대 방향**으로 가면 y가 줄어듦. 편미분 = 하나만 움직이기, 연쇄법칙 = 배율끼리 곱하기. day9 기초 1 \~ 실무 1 풀이.

## 왜 중요한가
- 큰 모델일수록 LoRA도 기반 모델을 BF16으로 올리는 것만으로 GPU를 넘는다(14B 27.5 GiB). QLoRA는 그 몸통까지 줄여서 "학습할 수 있느냐"를 바꾼다.
- 반대로 작은 모델에서 "4비트니까 1/4"을 믿으면 틀린다. 저장 · 계산 · 비양자화 층을 구분하고, **같은 구간에서 잰 숫자**로 판단해야 한다.
- 미분의 "기울기 반대 방향"과 연쇄법칙의 "배율 곱하기"가 결국 옵티마이저가 A · B를 고치는 방법이다. Ŵ도 기울기가 지나가지만 고치지 않을 뿐이다.

# 보강: 중앙 차분과 연쇄법칙
def central_diff(f, x, h=0.001):
    return (f(x + h) - f(x - h)) / (2 * h)

print(round(central_diff(lambda x: (2 * x + 1) ** 2, 1), 3))   # 12.0 = 2 × 2(2x + 1)

## 헷갈렸던 부분 & 해결
- **index × scale로 메모리를 줄인다?** 아님. 줄어드는 건 **번호 + scale만 저장**할 때. 곱하기는 쓸 때 되돌리는 단계.
- **정규분포 모양 코드북은 예제 얘기?** 아님. 예제는 균등 2비트, 0 근처가 촘촘한 건 NF4.
- **`[:, None]`.** (5,) → (5, 1). (1, 4)와 빼면 (5, 4) 거리 표, `argmin(dim=1)`로 행마다 번호.
- **4비트에서 NF4가 균등보다 오차가 큰 이유.** 예제 값(−0.45, 0.65)이 0 근처가 아니라 바깥쪽이라서.
- **32 · 64 · 256이 다 뭐야.** 32 = 숫자 하나의 크기(FP32), 64 = 가중치를 묶는 규칙, 256 = scale을 묶는 규칙. 기준값 하나가 256 × 64 = 16,384개 가중치를 담당해서 거의 공짜(0.002비트).
- **임베딩을 FP32로 바꾸는 건 양자화로 loss가 오를까 봐?** 반만 맞음. 양자화 오차를 메우는 게 아니라, 압축 안 된 층(임베딩 · Norm · logits)을 **학습 중 수치 안정적으로 계산**하려는 것. 대가가 +272 MB.
- **편미분 x² + 3y²를 x로 하면 2x + 3?** 틀림. y는 고정이라 3y²는 상수 → 0. ∂z/∂x = 2x, ∂z/∂y = 6y.
- **연쇄법칙 1단계 배율.** 안쪽 식에서 x 앞의 숫자. (3x + 2)²면 3 × 2(3x + 2) = 18x + 12 (처음엔 2로 곱해서 틀림).
- **`from q4 import central_diff`.** 되지만 q4.py의 테스트 코드까지 실행됨 → `if __name__ == "__main__":`로 막아야 함.
