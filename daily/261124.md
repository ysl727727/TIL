## 오늘 배운 것
- **DPO = 두 답 중 고르기.** 같은 질문 · 같은 규정에 chosen(모범답안)과 rejected(판단 하나만 틀림)를 붙여 48쌍(6유형 × 8). 과잉 보류와 근거 없는 단정을 **둘 다** 넣어야 한쪽으로 안 치우친다.
- **응답 점수 = 응답 토큰 log p의 합.** 답 전체 확률은 토큰 확률의 곱 → log로 합. 평균이면 "글자당 실력"이라 다른 목적함수.
- **계산 순서.** CE로 토큰 log p 꺼내기 → 응답별 합 → (policy − reference) × β = reward → chosen − rejected = margin → σ(margin) = 이길 확률 → −log = loss. 시작은 margin 0 · loss 0.6931(ln 2).
- **reference는 숫자로 얼린다.** 학습 전 SFT로 48쌍 점수를 한 번만 재서 [48, 2]로 저장 → 모델을 두 개 올릴 필요 없음.
- **β(채점 기준) ≠ lr(보폭).** β 0.1이면 margin 3에 logp 차이 변화 30이 필요하다.
- **loss는 성공, chosen은 추락.** lr 2e-5: loss 0.00004 · 48/48 margin 양수인데 chosen reward −5.73 · chosen logp −0.44 → −73.65, dev 형식 12/12 → 2/12. lr 2e-6이면 chosen +0.02 · 형식 12/12.
- **"과잉 보류 0/8"의 함정.** status를 못 읽은 8개가 어느 쪽에도 안 세져서 생긴 0.
- **저장 재현 ≠ 학습 재현.** 재로딩은 logits 차이 0.0 · 원문 일치, 다시 학습하면 형식 1/12 · 0/12 · 2/12로 흔들림.
- **보강 경사하강법.** 새 위치 = 위치 − lr × 기울기, x²에서 한 걸음은 (1 − 2·lr)배(크기 < 1 수렴, > 1 발산, 음수면 진동). MSE는 데이터가 고정이고 w, b가 다이얼인 함수, w · b 기울기는 둘 다 연쇄법칙. day10 기초 1 \~ 응용 3 통과.

## 왜 중요한가
- SFT로 정답을 따라 쓰게 해도 "이 판단이 저 판단보다 낫다"는 직접 가르치지 못한다. DPO는 판단 차이를 손실로 만든다.
- 그런데 손실은 **차이만** 봐서, 좋은 답까지 같이 떨어져도 loss는 줄어든다. 숫자 하나(loss)만 보고 "학습 성공"이라고 하면 문장이 깨진 모델을 내보내게 된다.
- 경사하강법의 "학습률이 크면 튕겨 나간다"가 실제 모델에선 2e-5 → 2e-6 차이로 나타났다. `optimizer.step()`은 결국 오늘 보강의 `x - lr * 기울기`다.

## 코드/예시
```python
# 손실 계산 순서를 toy로 직접 찍어 본 것 (B 2 · T 4 · V 6, 후보 균등)
toy_labels = torch.tensor([[-100, -100, 2, 5], [-100, -100, 2, -100]])
targets = toy_labels[:, 1:]            # [[-100, 2, 5], [-100, 2, -100]]
mask = targets.ne(-100)                # [[F, T, T], [F, T, F]]  → "남길 칸을 고르는 체"
# logits[:, :-1, :][mask] → (3, 6),  targets[mask] → [2, 5, 2]
# token_logps = [-1.7918] * 3  (= log 1/6),  owners = [0, 0, 1]
# sums = [-3.5835, -1.7918] (합: 긴 답이 낮음),  평균 = [-1.7918, -1.7918]

# dpo_terms: reference [-4, -3], policy [-3, -4] (좋아진 경우)
log_ratios = policy - reference        # [+1, -1]
rewards = 0.1 * log_ratios             # [+0.1, -0.1]
margin = rewards[0] - rewards[1]       # +0.2
loss = -F.logsigmoid(margin)           # 0.598 (시작 0.693보다 줄어듦)
# reference - policy로 반대로 빼면 margin -0.2 · loss 0.798 → 학습이 거꾸로
```

| 위치 | 마이너스 | 이유 |
|---|---|---|
| `-F.cross_entropy(...)` | 벌점 −log p → 점수 log p | CE가 손실용이라 −가 붙어 나옴 → 되돌림 |
| `-F.logsigmoid(margin)` | 점수 log σ → 벌점 −log σ | optimizer는 줄이는 방향으로만 → 좋은 답 쪽이 되게 |

```python
# 보강: 경사하강법으로 w, b 찾기
for i in range(3000):
    error = w * x + b - y
    w = w - lr * (2 * error * x).mean()
    b = b - lr * (2 * error).mean()      # 1.98 0.93 (정답 2x + 1에 잡음)
```

## 헷갈렸던 부분 & 해결
- **CE 하고 −sigmoid?** 큰 순서는 맞지만 ① CE 결과는 손실이 아니라 log p 점수 재료 ② 사이에 reference 비교 · margin 단계 ③ 마지막은 −sigmoid가 아니라 **−log sigmoid**.
- **log p는 0\~1 사이?** 0\~1은 p. log p는 −∞ \~ 0(항상 0 이하).
- **−log p는 점수가 클수록 벌점이 커져서 −를 붙인다?** 반대. log p가 **음수 점수**라서 −를 붙여 **양수 벌점**(잘 맞힐수록 0)으로 바꾸는 것.
- **"손실은 0 이상이고 작을수록 좋은 값"이 무슨 말?** 경사하강법이 값을 **줄이는** 방향으로만 가서 "좋아질수록 작아지는 값"이어야 한다. 0 이상(0 = 완벽)은 필수라기보다 읽기 편한 성질.
- **margin이 이길 확률?** 아님. margin은 격차(−∞ \~ +∞), σ(margin)이 확률(0\~1). 낮아져야 하는 건 reward\_rejected.
- **왜 −σ가 아니라 −log σ?** 쌍들의 확률 곱을 합으로 바꾸고, **틀릴수록 기울기가 커진다**(margin −4에서 −σ는 0.018, −log σ는 0.98).
- **두 번 − 할 거면 처음부터 안 붙이면?** 맞음. `log_softmax(...).gather(...)`면 − 없이 같은 값. CE의 −는 함수 성질이라 생긴 것.
- **mask가 −100이 아닌 자리?** 이름 탓. mask는 가리는 게 아니라 남길 칸을 고르는 체, 가림은 labels의 −100.
- **열은 왜 버려?** 열은 `[mask]`로 짝지을 때 이미 씀. 남은 건 응답별 더하기라 "몇 번째 응답"(행)만 필요.
- **어댑터에 DPO 적용?** 아님. 모델 전체 출력으로 DPO 손실을 계산하고 **고치는 게 A · B뿐**("LoRA로 DPO 한다"). reference는 어댑터를 끄면 공짜.
- **LoRA도 SFT야?** SFT는 "무엇을 배우나"(따라 쓰기), LoRA는 "어디를 고치나"(A · B). W' = W + (α/r)·BA로 보면 가중치가 바뀐 것.
- **SFT 뒤 다시 SFT면 재학습?** 이어 학습(추가 SFT)이 정확. 재개 = 같은 계획 이어 가기, 재학습 = 원본부터.
