## 오늘 배운 것
- **7장은 학습하지 않는다.** 보고서에 저장된 dev 답을 다시 채점하고, 3장 SFT 하나만 복원해서 API에 연결.
- **채점 전에 지문부터.** 보고서에 기록된 sha256과 지금 올린 파일의 sha256이 같아야 "같은 시험지". 지문 일치 = 같은 파일이지, 좋은 설정이라는 뜻은 아니다(2e-5로 무너진 DPO도 통과).
- **세 관문.** ① `json_object`(원문 그대로 `json.loads`, 코드 펜스 안 벗김) → ② `schema_ok`(키 3개 · 타입 · 상태와 인용 짝) → ③ `citation_ids_ok`(`issubset`). 실패는 **첫 실패 단계 하나만** 센다(합계 항상 12).
- **형식이 완벽한 오답.** "70,000원은 65,000원 이하 → 승인 불필요"도 세 관문 모두 True. full\_sft는 형식 12/12인데 over\_limit에서 바로 이 답을 냈다.
- **결과 (수업자료 L4 보고서):** base 0 · full\_sft **12** · lora 0 · qlora 0 · dpo 0 (/12). 슬라이드는 qlora 0 · dpo 2. 받은 dpo는 lr 2e-5라 JSON부터 다 깨짐.
- **API = 네 칸.** `AnswerRequest`(strict · extra forbid → 422) → `retrieve_documents`(팀 + 낱말 겹침) → `generate_answer`(3장 SFT) → `inspect_response`(200 / 502). 80,000원 질문은 **200인데 판단 틀림**, 통신비 질문은 보류로 맞음.
- **실패 칸 네 개.** 형식 · 검색 · 업무 판단 · 운영. 후보는 full\_sft로 고정하되 `deployment_ready: False`, test는 8장에서 처음.
- **통합 실습 TODO 1\~8.** `json.loads(raw)` · `schema_ok = True` · `issubset` / 숙박 낱말 · 팀 필터 · id · text만 / `retrieve_documents` · `generate(model, row)`.

## 왜 중요한가
- "모델이 좋아졌다"를 말하려면 **같은 파일 · 같은 문항 · 같은 생성 설정**이 먼저다. 출처가 다르면 숫자를 나란히 놓을 수 없다.
- 자동 검사 · HTTP 200은 "약속(JSON 계약)을 지켰다"까지만 말해 준다. 금액 대소 · 승인 시점은 사람이 원문을 읽어야 하고, 그래서 API 응답에도 `review_required: True`를 붙인다.
- 실패를 칸으로 나눠야 고칠 곳이 보인다. 검색이 문서를 못 찾았는데 재학습하면 헛수고고, 금액 비교처럼 답이 하나인 규칙은 코드로 계산하는 선택지도 있다.

# 코드 펜스를 벗기고 싶다면: result는 그대로, 입력을 바꾸고 두 점수를 따로
FENCE = re.compile(r"\s*```(?:json)?\s*(.*?)\s*```\s*", re.S)

def strip_fence(raw):
    m = FENCE.fullmatch(raw)
    return (m.group(1), True) if m else (raw, False)

text, fence_removed = strip_fence(raw)
strict = inspect_response(raw, source_ids)     # 교안 기준 (펜스 = 약속 위반)

# result에 "fenced" 키를 넣으면 all(values()) · 첫 실패 단계가 깨짐

## 헷갈렸던 부분 & 해결
- **dev가 뭐지?** development(개발용) = validation 데이터. train 48(8팀, 학습) · dev 12(가온 · 마루, 중간 비교 · 후보 고르기) · test 12(2팀, 마지막 한 번). 비유하면 연습문제 · 모의고사 · 수능. dev는 3~6장 내내 봤으니 dev 12/12를 일반화 성능이라고 말하지 않는다.
- **코드 펜스를 지우려면 result를 어떻게?** result는 안 바꾼다. 떨어지는 곳이 `json.loads`라서 그 **앞의 입력**을 바꾼다. result에 키를 추가하면 `all()`과 첫 실패 단계가 깨지고, 함수 안에서 벗기면 자기 점검 assert가 깨진다.
- **6장 `inspect_response`와 뭐가 달라?** 6장은 `format_ok` 하나 + `status`(보류 · 단정 세기), 7장은 관문별 bool 3개(어디서 떨어졌나 보기).
