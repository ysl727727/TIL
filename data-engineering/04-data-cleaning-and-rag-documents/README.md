## Core Theory

### 1. 정제는 "지우기"가 아니라 "판정하고 기록하기"

3장까지는 받은 그대로 저장하는 것이 목표였다. 4장은 그 원본을 **바꾸지 않고**, 정제 결과를 별도 산출물로 만든다. 원본을 덮어쓰면 "원래 어떤 값이었는지"를 되돌릴 수 없어 정제 규칙이 틀렸을 때 확인할 방법이 사라진다.

정제 단계에서 만드는 산출물은 두 가지다 — 정제된 문서 목록, 그리고 무엇을 몇 건 제외했는지 적은 요약.

### 2. 수집 직후 자주 나타나는 다섯 가지 문제

| 문제 | 예시 | 처리 |
| --- | --- | --- |
| 결측 | `title`이 없거나 `content`가 빈 문자열 | 필수 필드가 비면 제외 |
| 중복 | 같은 `id`가 여러 페이지에 등장 | 먼저 본 것만 남김 |
| HTML 태그 | `<p>본문</p>`, `&amp;` | 태그 제거 + 엔티티 복원 |
| 공백 | 줄바꿈·탭·연속 공백 | 하나의 공백으로 정규화 |
| 날짜 형식 | `2026/07/16`, `16-07-2026` | 하나의 표기로 통일 |

다섯 가지를 한 함수에 몰아넣지 않고 **각 문제를 판정하는 함수와, 그 판정을 모아 한 건을 통과/제외로 결정하는 함수**를 나눈다.

### 3. 텍스트 정제 순서가 고정인 이유

```python
import html, re

def clean_text(raw: str) -> str:
    text = html.unescape(raw)               # 1) &amp; → &  (엔티티 먼저 복원)
    text = re.sub(r"<[^>]+>", " ", text)    # 2) 태그를 공백으로 치환
    return " ".join(text.split())           # 3) 연속 공백·줄바꿈을 한 칸으로
```

- 엔티티 복원을 **먼저** 해야 `&lt;p&gt;`처럼 이스케이프된 태그도 2단계에서 함께 제거된다.
- 태그를 빈 문자열이 아니라 **공백**으로 바꾼다. `<p>앞</p><p>뒤</p>`를 빈 문자열로 지우면 `앞뒤`가 붙어 두 문장이 한 단어처럼 된다.
- `" ".join(text.split())`은 앞뒤 공백 제거·연속 공백 축약·줄바꿈 제거를 한 번에 한다.

`re.sub(r"<[^>]+>", ...)`는 완전한 HTML 파서가 아니다. 부등호가 본문에 그대로 들어간 문서에서는 잘못 지울 수 있으므로, 입문 단계에서는 "수집한 뉴스 본문 정도"에만 적용한다고 범위를 정해 둔다.

### 4. 중복 판정과 집계 등식

```python
seen_ids: set[str] = set()

for row in rows:
    if row["id"] in seen_ids:
        duplicated += 1
        continue
    seen_ids.add(row["id"])
```

`list`로 `in`을 검사하면 건수가 늘어날수록 느려지고, `set`은 길이와 거의 무관하게 확인된다.

정제가 끝나면 다음 등식이 반드시 성립해야 한다.

```text
입력 건수 = 정상 건수 + 중복 제외 건수 + 규칙 제외 건수
```

이 등식이 맞지 않으면 어딘가에서 조용히 사라진 건이 있다는 뜻이다. **합계를 먼저 맞춰 보는 것이 정제 코드의 가장 빠른 검증 방법**이다.

### 5. RAG 문서 한 건의 계약

검색 단계에서 쓰기 좋은 문서는 세 부분으로 나뉜다.

| 부분 | 역할 | 주의 |
| --- | --- | --- |
| `document_id` | 문서를 가리키는 고유 이름 | 중복 불가, 사람이 읽을 수 있게 |
| `content` | 실제로 임베딩·검색 대상이 되는 본문 | 태그·군더더기 제거된 상태 |
| `metadata` | 출처·날짜·카테고리 등 필터와 인용에 쓰는 값 | 본문에 섞지 않음 |

출처와 날짜를 본문 안에 문장으로 넣으면 검색 결과에 섞여 답변 품질이 흔들린다. **필터에 쓸 값은 `metadata`, 읽을 내용은 `content`** 로 분리한다.

### 6. `document_id` 만들기

```python
def make_document_id(source: str, index: int) -> str:
    slug = re.sub(r"[^a-zA-Z0-9-]+", "-", source).strip("-").lower()
    return f"doc-{slug}-{index:03d}"
```

`doc-news-001`처럼 **접두사 + 출처 슬러그 + 일련번호** 형태로 만든다.

- 허용 문자만 남기고 나머지를 `-`로 바꾸면 공백·한글·기호가 섞여도 파일명과 URL에 안전한 값이 된다.
- `.strip("-")`으로 앞뒤에 남은 `-`를 정리하고, `.lower()`로 대소문자 차이 때문에 다른 ID로 취급되는 일을 막는다.
- `{index:03d}`는 정렬했을 때 `doc-news-10`이 `doc-news-2`보다 앞에 오는 문제를 없앤다.

원본 `id`가 이미 고유하면 그것을 그대로 써도 된다. 다만 **출처가 여럿이면 원본 ID끼리 충돌할 수 있으므로 출처를 ID에 포함**한다.

### 7. 저장과 재확인

```python
path.write_text(json.dumps(documents, ensure_ascii=False, indent=2), encoding="utf-8")
reloaded = json.loads(path.read_text(encoding="utf-8"))
assert len(reloaded) == len(documents)
```

저장으로 끝내지 않고 **다시 읽어서 건수와 한글이 그대로인지 확인**한다. `ensure_ascii=False`가 빠지면 한글이 `\uXXXX`로 저장되어 눈으로 검수하기 어렵고, `indent=2`가 없으면 한 줄짜리 파일이 되어 diff를 볼 수 없다.

## Questions and Newly Learned Points

- 정제와 수집을 한 스크립트에 합치면 "받은 값"과 "고친 값"의 경계가 사라진다 — 3장의 원본 파일을 입력으로 받아 4장이 새 파일을 만드는 구조가 되돌리기 쉽다.
- 제외한 건은 개수만 세지 말고 **왜 제외했는지**도 함께 남겨야 한다. 같은 "제외 3건"이라도 결측 때문인지 중복 때문인지에 따라 다음에 고칠 곳이 다르다.
- `strip()`은 앞뒤 공백만 없애고 문장 가운데의 연속 공백은 남는다 — `split()` + `join()`이 필요한 이유.
- 자주 하는 오해: "태그만 지우면 정제는 끝이다"(엔티티와 공백이 남는다) / "중복은 본문이 같은 것만 뜻한다"(ID가 같은 것이 먼저다) / "ID는 랜덤 UUID가 제일 안전하다"(고유하긴 하지만 어떤 문서인지 사람이 알아볼 수 없어 디버깅이 어렵다) / "metadata는 나중에 붙여도 된다"(임베딩 이후에는 원본 대응을 다시 찾아야 한다).
