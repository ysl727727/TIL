# 2회차. IP와 서브넷팅 — IPv4/IPv6 · 고정/유동 IP · DHCP · 서브넷 마스크 · CIDR

> 2026-10-30 네트워크 스터디("TCP 한 잔 할래요?") 2회차 기록이에요. 면접에서는 **정의로 답하고, 비유로 떠올린다**는 방식으로 정리했어요.

## 큰 흐름

```text
IP(규약) → IP 주소(연결마다 붙는 논리 주소) → IPv4 32비트 / IPv6 128비트
→ 주소를 받는 방법: 유동(DHCP 임대) / 고정(직접 설정)
→ 주소를 나누는 방법: 네트워크 부분 + 호스트 부분, 경계는 서브넷 마스크(CIDR /n)
→ 계산: 블록 크기 → 블록 나누기 → 어느 블록인지 → 네트워크·브로드캐스트·범위·대수
```

## 핵심 정리

### 1. IP와 IP 주소

| 용어 | 정의 | 비유 |
| --- | --- | --- |
| IP (Internet Protocol) | 패킷에 출발지·목적지 주소를 붙이고 그 주소로 전달하게 하는 **통신 규약** | 택배 송장 쓰는 규칙 |
| IP 주소 | 네트워크에 연결된 각 **연결(인터페이스)**을 구분하고 위치를 나타내는 논리 주소. 같은 네트워크에서 겹치면 안 되고, 기기가 아니라 연결마다 하나 | 송장의 받는 사람 주소 |

### 2. IPv4 vs IPv6

| | IPv4 | IPv6 |
| --- | --- | --- |
| 길이 | 32비트 (8비트 옥텟 × 4) | 128비트 (16비트 × 8묶음) |
| 표기 | 0~255 숫자, 점(`.`) | 16진수, 콜론(`:`) |
| 개수 | 약 43억 (2³²) | 약 3.4 × 10³⁸ |
| 나 자신 | `127.0.0.1` | `::1` |

- IPv6 줄여 쓰기: 각 묶음 앞의 0은 생략, **연속된 0 묶음은 `::`로 딱 한 번**(길이가 같으면 앞쪽). 예: `2001:0db8:0000:…:0001` → `2001:db8::1`.
- 사설 IP와 NAT로 IPv4를 아껴 쓰고 있어서 지금은 둘을 함께 써요(듀얼 스택).

### 3. 유동 IP vs 고정 IP

| | 유동 IP | 고정 IP |
| --- | --- | --- |
| 정의 | DHCP 서버가 정해진 기간(Lease Time) 동안 자동으로 빌려주는 IP, 바뀔 수 있음 | 관리자가 직접 설정하거나 통신사가 계속 같은 주소로 주는 IP |
| 쓰는 곳 | 노트북 · 휴대폰 | 서버 · DB · 프린터 (IP 관리대장으로 관리) |
| 비유 | 열람실 좌석 배정 | 우리 집 주소 |

- **DHCP**: IP · 서브넷 마스크 · 게이트웨이 · DNS 서버를 자동으로 나눠 주는 프로토콜. 순서 DORA = ① Discover(방송으로 찾기) ② Offer(제안) ③ Request(요청) ④ Ack(확정).
- **리스 타임 vs 세션 타임**: 리스 타임은 DHCP가 IP를 빌려주는 기간(절반쯤 지나면 연장 요청), 세션 타임은 로그인·인증된 접속을 유지하는 시간(끝나면 재인증). 세션이 끝나도 IP는 그대로일 수 있어요.
- 고정 IP를 넣을 때는 **IP · 서브넷 마스크 · 기본 게이트웨이 · DNS** 네 가지를 함께 넣고, 번호는 DHCP 범위 밖에서 골라요(겹치면 충돌).

### 4. 서브넷팅

| 용어 | 정의 | 비유 |
| --- | --- | --- |
| 네트워크 / 호스트 부분 | IP 앞쪽 비트는 네트워크, 뒤쪽 비트는 그 안의 기기. 경계는 서브넷 마스크가 정함 | 101동 / 1003호 |
| 서브넷 · 브로드캐스트 | 네트워크를 더 작게 나눈 네트워크 / 같은 서브넷 전체에 한 번에 보내는 통신 | 단지를 동으로 나누면 방송이 그 동에만 |
| 서브넷 마스크 | 네트워크 부분은 1, 호스트 부분은 0으로 표시한 32비트 값 (`255.255.255.0`) | 주소 위에 대는 투명 자 |
| CIDR | IP 뒤에 `/`와 마스크의 1 개수 (`255.255.255.0` = /24, `.192` = /26) | "앞 24칸이 동" |
| 네트워크 · 브로드캐스트 주소 | 호스트 부분이 모두 0(서브넷 자체) / 모두 1(전체 방송). **둘 다 기기에 못 줌** | 동 이름표 / 안내 스피커 |
| 기본 게이트웨이 | 다른 네트워크로 가는 패킷을 받아 전달하는 장치(보통 라우터)의 IP, 관례상 서브넷의 첫 주소 | 단지 정문 |

- **IP 주소 클래스**(옛 방식): A 1~126 /8 · B 128~191 /16 · C 192~223 /24 · D 224~239 멀티캐스트 · E 240~ 실험용 · 127은 루프백. 크기가 고정이라 낭비가 커서 지금은 CIDR로 대체.

### 5. 2진수 변환

- 옥텟 자릿값: 128 · 64 · 32 · 16 · 8 · 4 · 2 · 1 (2⁷ ~ 2⁰). 비유: 1·2·4…128원 동전.
- 10 → 2진수: 2로 나눈 나머지를 아래에서 위로. `200 = 11001000` (128 + 64 + 8)
- 2 → 10진수: 1인 자리의 값을 더하기. `10101000 = 128 + 32 + 8 = 168`

### 6. 서브넷 계산 4단계

```text
블록 크기 = 2^(호스트 비트 수) = 256 − 마스크 마지막 칸      호스트 수 = 블록 − 2

/24 256·254   /25 128·126   /26 64·62   /27 32·30   /28 16·14   /29 8·6   /30 4·2
```

`192.168.10.77/26` 예시:

1. 블록 크기: /26 → 마스크 마지막 칸 192 → 256 − 192 = **64**
2. 0부터 64씩 나누기: 0~63 · 64~127 · 128~191 · 192~255
3. 77은 **64~127** 블록
4. 네트워크 `.64` · 브로드캐스트 `.127` · 사용 범위 `.65 ~ .126` · **62대**

- −2를 하는 이유: 호스트 부분이 모두 0인 네트워크 주소와 모두 1인 브로드캐스트 주소는 기기에 줄 수 없어서.

## 같이 푼 문제

| 문제 | 답 |
| --- | --- |
| `10.0.0.1` / `fe80::1` / `256.1.1.1` | IPv4 / IPv6 / 둘 다 아님(옥텟은 255까지) |
| `2001:0db8:0000:0000:0000:0000:0000:0001` 줄이기 | `2001:db8::1` |
| 200 → 2진수, `11110000`·`10101010` → 10진수 | `11001000` · 240 · 170 |
| /25 마스크, `255.255.255.240`의 CIDR | `255.255.255.128` · /28 |
| `172.16.5.200` · `224.0.0.5` 클래스 | B · D(멀티캐스트) |
| /27 블록 · 호스트 | 32 · 30대 |
| `10.0.0.130/25` | 네트워크 .128 · 브로드캐스트 .255 · 126대 |
| `172.16.5.200/27` | .192 · .223 · 30대 (200은 192~223 블록) |
| 호스트 30대가 필요하면 | /27 (32 − 2 = 30) |
| `.10/28`과 `.20/28`은 같은 서브넷? | 아니요 — 블록 16이라 0~15와 16~31로 다른 동 |

## 면접 예상 질문 (내 말로)

- **IP와 IP 주소의 차이?** IP는 패킷에 주소를 붙여 전달하는 규약이고, IP 주소는 그 규약에서 각 연결을 구분하는 논리 주소예요.
- **IPv4와 IPv6의 차이?** IPv4는 32비트(약 43억 개)를 10진수와 점으로, IPv6는 128비트를 16진수와 콜론으로 써요.
- **고정 IP와 유동 IP?** 고정은 늘 같은 주소(서버·DB), 유동은 DHCP가 임대해 줘서 바뀔 수 있는 주소(노트북·폰)예요.
- **서브넷 마스크란?** 네트워크 부분을 1, 호스트 부분을 0으로 표시한 32비트 값이에요. `255.255.255.0` = /24.
- **호스트 수에서 2를 빼는 이유?** 네트워크 주소(호스트 비트 모두 0)와 브로드캐스트 주소(모두 1)는 기기에 줄 수 없어서예요.
- **192.168.10.77/26의 네트워크 주소?** 192.168.10.64. /26은 블록 64이고 77은 64~127 블록이에요.

## 확인 문제

### NET2-Q1. CIDR

`255.255.255.224`를 CIDR로 쓰면?

① /26  
② /27  
③ /28  
④ /29

<details>
<summary>정답 보기</summary>

**②** — 224 = `11100000`이라 마지막 칸에 1이 3개, 24 + 3 = 27. 블록은 256 − 224 = 32.

</details>

### NET2-Q2. 브로드캐스트 주소

`192.168.1.100/28`의 브로드캐스트 주소는?

① 192.168.1.255  
② 192.168.1.96  
③ 192.168.1.111  
④ 192.168.1.112

<details>
<summary>정답 보기</summary>

**③** — /28은 블록 16 → 96~111 블록에 100이 있어요. 네트워크 .96(②), 브로드캐스트 .111, 사용 범위 .97~.110(14대).

</details>

### NET2-Q3. 고정 IP 설정

서버에 고정 IP를 넣을 때 맞는 설명은?

① IP 주소 하나만 넣으면 된다  
② DHCP 범위 안의 비어 보이는 번호를 고른다  
③ 브로드캐스트 주소를 써도 된다  
④ IP · 서브넷 마스크 · 기본 게이트웨이 · DNS를 함께 넣고, DHCP 범위 밖 번호를 고른다

<details>
<summary>정답 보기</summary>

**④** — 지금 비어 보여도 DHCP 범위 안이면 나중에 다른 기기에 임대돼 충돌할 수 있어요(②). 브로드캐스트 주소는 기기에 못 줘요(③).

</details>

### NET2-Q4. IPv6 줄여 쓰기

`fe80:0000:0000:0000:0000:0000:0000:0001`을 바르게 줄인 것은?

① fe80::1  
② fe8::1  
③ fe80:0:0::1::  
④ fe80::0001::

<details>
<summary>정답 보기</summary>

**①** — 앞의 0만 생략할 수 있어서 `fe80`의 뒤쪽 0은 못 지워요(②). `::`는 딱 한 번만 쓸 수 있어요(③·④).

</details>

### NET2-Q5. 서술형 — 리스 타임과 세션 타임

리스 타임과 세션 타임의 차이를 설명하고, 세션이 끝나도 IP가 그대로일 수 있는 이유를 써라.

<details>
<summary>예시 답안</summary>

리스 타임은 DHCP가 IP를 빌려주는 기간이고(절반쯤 지나면 기기가 연장을 요청), 세션 타임은 로그인·인증된 접속을 유지하는 시간이라 끝나면 다시 인증해요. 둘은 관리하는 대상이 달라요. 주소 임대는 DHCP가, 접속 인증은 인증 시스템이 맡아요. 그래서 세션이 끝나 재로그인하더라도 리스가 남아 있으면 같은 IP를 계속 써요.

</details>

### NET2-Q6. 서술형 — 30대가 들어가는 서브넷

호스트 30대가 들어갈 가장 작은 서브넷의 CIDR과 그 이유를 블록 크기로 설명하라.

<details>
<summary>예시 답안</summary>

/27이에요. 블록 크기는 2^(호스트 비트 수)이고, 쓸 수 있는 기기 수는 네트워크·브로드캐스트 주소를 빼서 블록 − 2예요. /28은 16 − 2 = 14대라 부족하고, /27은 32 − 2 = 30대라 딱 맞아요. 호스트 비트 5개 → 32 − 5 = 27.

</details>
