# 프로젝트(1) 회고 — 오픈소스 LLM 선정: 부동산 허위매물 탐지 어시스턴트

> 2026-09-14 ~ 09-18, 개인 수행. 과정의 첫 프로젝트 "오픈소스 LLM 활용"입니다. 목표는 모델을 실행해 보는 게 아니라 **"우리 서비스에는 어떤 LLM을 써야 하는가?"에 근거를 갖고 답하기**였습니다. 국토교통부 표시·광고 기준으로 매물 광고 위반을 판정하는 어시스턴트를 가정하고, 같은 조건(4B · Q4_K_M)의 로컬 모델 두 개를 비교해 골랐습니다.
>
> 전체 보고서와 코드: [ysl727727/real-estate-fake-listing-detector](https://github.com/ysl727727/real-estate-fake-listing-detector)

## 한눈에

| 항목 | 내용 |
| --- | --- |
| 업무 | 매물 광고 정보를 고시 조항에 대조해 `판정 / 유형 / 근거`를 내는 검수 어시스턴트 (in-context QA, RAG 없음) |
| 후보 | `gemma3:4b` vs `qwen3:4b-instruct-2507-q4_K_M` (Ollama, 4B · Q4_K_M 동일) |
| 평가 | 고정 10문항(정상 5 · 경계 3 · 범위밖 2) × 2회, 체크리스트 채점 |
| 결과 | 답변 정확성 gemma3 **57.0%** · qwen3 **80.8%** |
| 선정 | **qwen3:4b-instruct-2507-q4_K_M** |
| 환경 | RTX 5060 Laptop (VRAM 8GB), uv, Ollama, Cloud 비교용 OpenAI API |

## 무엇을 했나

1. **주제 선정 이유:** 공식 판정 기준이 있어서 정답이 객관적으로 정해져요. "방향 90도 이상 차이" 같은 숫자 기준이 있어 경계 사례(45도 = 미해당)를 만들 수 있고, 미검수 매물 정보를 다루니 로컬 운영의 근거도 돼요.
2. **기준을 실험 전에 확정:** 결과를 보고 정하면 짜맞추기라서 먼저 정했어요.
   - 필수 통과 조건(되냐 안 되냐): 8GB VRAM GPU 실행, 상업적 사용 가능 License, 4,096 context, **자료 밖 내용 미생성**
   - 선호 순위: ① 환각 회피 ② 정확성 ③ 응답 시간 ④ VRAM
   - 가중치 총점은 쓰지 않았어요. 속도 점수로 환각 결함이 상쇄되면 안 돼서.
3. **조건 통제:** system 프롬프트, temperature 1, seed 42, num_predict 1,024, num_ctx 4,096을 고정. temperature·seed 불일치를 발견해 실험을 3회 다시 돌렸고(55.1/85.0 → 50.1/75.6 → **57.0/80.8**) 세 번 모두 선정 결과가 같았어요.
4. **채점:** 문항별 `expected` 체크리스트 1점씩 → 달성률(%) → 10문항 평균. 점수 근거 문장을 `scores.csv`의 `note`에 인용.

## 결과

| 유형 | gemma3 | qwen3 |
| --- | --- | --- |
| 정상 (5문항) | 68.5% | **100%** |
| 경계 (3문항) | 42.5% | **66.7%** |
| 범위밖 (2문항) | 50.0% | **54.2%** |
| **전체** | **57.0%** | **80.8%** |

| 성능 | gemma3 | qwen3 |
| --- | --- | --- |
| VRAM | **2,742 MiB** | 3,031 MiB |
| 전체 응답 시간 | **1.48초** | 2.22초 |
| 생성 속도 | 82 tok/s | **101 tok/s** |

- gemma3는 "자료 밖 내용 미생성" 필수 조건에서 탈락했어요. 속도·VRAM은 gemma3가 낫지만 실험 전에 정한 순서대로 1순위를 먼저 적용했어요.
- **결정적 사례(Q07):** 자료에 "다른 매물을 권유한 사실도 확인되지 않음"이라고 적혀 있는데, gemma3는 "확인되었습니다"로 **부정을 긍정으로 거꾸로 읽고** 위반이라고 판정했어요(2회 모두). qwen3는 기망 행위 불성립으로 미해당.

## 배운 것

- **기준은 비교 전에 정한다.** 결과를 보고 기준을 바꾸면 비교가 의미 없어져요. 2차 프로젝트 회고와 RAG 8장 평가(dev로 고르고 test는 마지막)까지 이어진 원칙이에요.
- **빠르지만 틀린 답보다 조금 느려도 맞는 답.** 잘못 판정하면 멀쩡한 중개사가 제재를 받거나 진짜 허위매물이 넘어가요.
- **같은 조건을 맞추는 게 실험의 절반.** 파라미터 규모·양자화·instruct 여부·temperature·seed를 맞춰야 차이를 "모델 차이"라고 말할 수 있어요. Cloud 모델은 `reasoning_tokens`를 실측해 추론이 꺼져 있었는지까지 확인했어요.
- License 확인과 "실제로 써도 되는가"는 별개(딥러닝 심화 5장 Model Card 읽기). gemma3는 조건부 충족이었어요.
- 정확한 서술 습관: "이 모델은 추론을 쓰지 않는다"가 아니라 "**본 구성에서** 사용되지 않았다".

## 한계

- 10문항 × 2회라 작은 평가 세트예요. 순위를 일반화하기 어려워요.
- in-context QA라 조항을 직접 넣었어요. 실제 서비스라면 조항 검색(RAG)이 필요해요.
- VRAM은 응답 직후 조회값이라 최대 사용량이 아니에요.
