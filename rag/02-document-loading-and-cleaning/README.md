# 2장. 문서 로딩 · Metadata · 정제 · JSONL 저장

> 2026-10-19 학습 기록. RAG 1일차 오후 수업입니다. 같은 숙박 규정을 TXT·HTML·PDF에서 읽어 `Document`로 만들고, 출처 metadata를 붙이고, 뜻은 그대로 둔 채 정제한 뒤, `documents.jsonl`로 저장하고 다시 읽어 검수하는 흐름을 정리했습니다. 네 강의 실습 문제(q\_easy·q\_hard)를 모두 직접 풀었습니다.

## 학습 목표

- 같은 규정을 TXT·HTML·PDF에서 추출하고, 형식마다 본문 밖 글자(메뉴, 제목, 하단 표기)가 섞이는 지점을 설명한다.
- 본문은 `page_content`, 출처·버전·상태는 `metadata`로 나누고, 현행 여부는 게시일이 아니라 `status`로 고른다.
- 공백·하단 표기·복사본 중복은 정리하되 금액·조건·부정 표현은 바꾸지 않는다.
- 문서 하나를 JSONL 한 행으로 저장하고, 다시 읽으며 행 번호와 함께 문법 오류·스키마 오류를 구분한다.

## 전체 흐름

### 한 문장

**검색 품질은 재료에서 시작합니다. 파일에서 본문만 정확히 꺼내고, 어디서 온 어떤 버전인지 꼬리표를 붙이고, 뜻은 건드리지 않고 정리해서, 다음 단계가 그대로 읽을 수 있게 저장합니다.**

### 왜 필요한가

```text
HTML 태그만 지우면     → "홈", "규정 목록" 같은 메뉴와 하단 문의 문구가 본문에 섞임
PDF 줄을 그대로 쓰면   → "정산할 수 / 있습니다"처럼 페이지 폭 때문에 문장이 끊김
게시일로 현행을 추측   → 초안이나 시행 예정 문서가 현행으로 잘못 선택될 수 있음
매끄럽게 고쳐 쓰면     → "자동 정산되지 않습니다" → "자동 정산됩니다"로 뜻이 뒤집힐 수 있음
```

**비유:** 도서관에 책을 들이는 과정과 같습니다. 포장지를 벗기고(로딩), 청구기호·판수·입고일 라벨을 붙이고(metadata), 같은 책이 두 권 들어왔으면 한 권만 꽂되 **개정판과 초판은 둘 다 보관**하고(중복 vs 버전), 대출 시스템에 등록한 뒤 실제로 조회되는지 확인합니다(저장·검수).

### 그림으로 보기

```text
raw/travel.txt  ─ read_text(utf-8) ───────────────┐
raw/travel.html ─ HTMLParser: <p> 안만 수집 ───────┼─→ 본문 문자열 ─→ Document
raw/travel.pdf  ─ pypdf extract_text → 제목·하단 제외 ┘                ├─ page_content : 검색할 본문
                                                                      └─ metadata     : document_id · title · status
                                                                                        version · category · source_url
        │ 2-3 정제: NFC + [ \t]+ → 한 칸 / 하단 표기 제거 / 중복 키(version, category, 본문 해시) / 빈 본문 제외
        ▼
documents.jsonl (12행, 한 행 = 문서 하나) ─→ load_jsonl: 행 번호 + inspect_line 검사 ─→ 3장 청킹 입력
```

### 강의 흐름

1. **2-1 꺼내기** — TXT는 인코딩, HTML은 본문 범위(`<p>`), PDF는 줄바꿈·제목·하단을 확인. 형식이 달라도 `Document` 하나의 모양으로 통일.
2. **2-2 꼬리표 붙이기** — `document_id`와 `metadata`(제목·분류·상태·버전·게시일·URL). 필드마다 쓰는 곳을 정하고, 청크별 정보는 `deepcopy` 뒤에 추가.
3. **2-3 깨끗하게** — 한 줄 안의 공백만 정리, 실제 하단 문자열만 제거, 같은 문서 복사본만 제외. 지운 줄은 따로 반환해 검토.
4. **2-4 저장·검수** — `json.dumps(..., ensure_ascii=False)`로 한 줄씩 저장하고, 다시 읽어 행 번호와 함께 오류를 보고.

## 핵심 이론

### 1. 형식별 로딩과 Document 구조 (2-1강)

| 입력 형식 | 읽는 방법 | 이번에 본 차이 | 다음에 할 일 |
| --- | --- | --- | --- |
| TXT | `Path.read_text(encoding="utf-8")` | 본문만 있는 문자열 | 인코딩과 빈 본문 확인 |
| HTML | `HTMLParser`로 `<p>` 안 텍스트만 수집 | 메뉴·제목·본문·하단이 서로 다른 태그 | 본문 범위 선택, 문단 순서 유지 |
| PDF | `pypdf`의 `pages[0].extract_text()` | 페이지 폭 줄바꿈, 제목·하단 표기 포함 | 페이지와 본문 범위 구분 |

- HTML에서 **태그만 지우면 메뉴와 문의 문구의 글자도 남습니다.** 본문이 어디에 있는지(이번엔 `<p>`) 먼저 정합니다. `HTMLParser`는 태그 시작·끝·글자를 만날 때마다 `handle_starttag`·`handle_endtag`·`handle_data`를 자동으로 부르고, `in_p` 스위치가 켜졌을 때만 글자를 모읍니다.
- PDF 추출 결과의 줄바꿈은 **문단 끝이 아니라 페이지 폭** 때문일 수 있습니다. 스캔 이미지 PDF는 텍스트 계층이 없어서 OCR이 필요합니다.
- 실습: 빈 줄을 뺀 줄 목록에서 `lines[1:-1]`(첫 줄 제목, 끝 줄 하단 제외)을 공백으로 이어 붙이면 travel 원문과 `==`로 같아짐. 단, 이 규칙은 **이 샘플 배치에만** 맞습니다.
- `Document(page_content=본문, metadata={**기존_metadata, "document_id": ..., "format": "html"})` — 같은 규정의 TXT·HTML·PDF는 규정 3개가 아니라 **수집 경로 3개**입니다.

### 2. 출처 추적을 위한 Metadata (2-2강)

| 필드 | travel 예시 | 사용 위치 |
| --- | --- | --- |
| `document_id` | travel | 원문 찾기, 청크와 연결 |
| `content` | 숙박 한도·영수증·초과 승인 본문 | 청킹, 임베딩, Context |
| `metadata.title` | 출장 숙박 정산 | 검색 결과 제목, 인용 표시 |
| `metadata.status` / `version` | current / v2 | 현행 선택, 버전 구분 |
| `metadata.category` | 출장 | 분야별 필터 |
| `metadata.source_url` | 원문 위치 | 원문 링크 |

- travel `v2 · 2026-08-01 · current` vs travel-old `v1 · 2025-01-01 · retired`. **게시일만으로 현행을 추측하지 않고** 기록된 `status`를 씁니다.
- 인용 표시 `제목 (버전) | URL` → 같은 주제의 두 버전을 구분하기 쉬움.
- 청크마다 `section`을 다르게 붙일 때는 `deepcopy`. `left = travel["metadata"]`처럼 대입하면 같은 객체를 가리켜 원문이나 다른 청크까지 바뀝니다.
- **본문 해시**(sha256)는 내용이 정확히 같은지 비교하는 값이지 의미 유사도가 아닙니다. 공백 하나만 달라도 바뀝니다. 원문 ID·버전·해시는 서로 다른 정보입니다.
- 실습 `choose_current(docs, category)`: `category`와 `status == "current"`를 **둘 다** 검사 → `출장`이면 travel, meal (travel-old 제외).

### 3. 정제 — 지울 것과 지키는 것 (2-3강)

- 공백: `unicodedata.normalize("NFC", text)` 후 `re.sub(r"[ \t]+", " ", ...)`.strip(). `\s+`를 쓰면 **줄바꿈까지 합쳐져** 문단·목록·표 구조가 사라질 수 있습니다. `repr`(f-string에선 `!r`)로 찍으면 탭과 양끝 공백이 보입니다.
- PDF 하단 표기(`교육용 가상 규정 · 2026-08-01 · 1`)는 **실제 문자열을 보고 그 줄만** 제거. 반복된다는 이유로 숫자·날짜를 일괄 삭제하면 본문 금액까지 사라집니다.
- 중복: **중복 키 = (version, category, sha256(본문))**. travel 복사본을 하나 붙인 13개 → 12개, travel과 travel-old는 둘 다 유지(구버전은 나중에 필터가 담당).
- 근접 중복(일부만 다른 문서)은 해시가 다릅니다. 지우기 전에 금액·시행일·예외 조건 차이를 비교합니다.
- **윤문·요약은 정제가 아닙니다.** 부정 표현 하나만 바뀌어도 규정 뜻이 반대가 됩니다.

| 수정 | 이번 처리 | 확인할 결과 |
| --- | --- | --- |
| 연속 공백·탭 | 한 줄 안에서 한 칸으로 | 단어와 문장 유지 |
| PDF 줄 연결 | 본문 범위를 고른 뒤 공백으로 | 끊긴 문장 이어짐 |
| 반복 하단 | 일치하는 표기만 제외 | 본문 날짜·금액 보존 |
| 윤문·요약 | 하지 않음 | 원문 조건 그대로 |

- 빈 본문: `if not doc["content"].strip()` → `rejected`에 `(ID, "빈 본문")` 기록.
- 실습 `clean_lines(text, footer)` → `(정리한 본문, removed)`를 **같이 반환**. footer와 정확히 같은 줄만 지우므로 footer를 잘못 넘겨도 에러가 없고, `removed`를 봐야 알 수 있습니다.

### 4. JSONL 저장과 검수 (2-4강)

- **직렬화** = Python 객체 → 저장 가능한 문자열. `json.dumps`는 문자열을 반환하고 `json.dump`는 파일에 씁니다. `ensure_ascii=False`는 한글을 그대로 남기는 옵션이고, 파일 인코딩(UTF-8) 지정과는 별개입니다.
- **JSONL** = 한 줄에 JSON 객체 하나. 행 사이 쉼표·전체 대괄호 없음. `indent`를 쓰면 객체 하나가 여러 줄로 나뉘어 형식이 깨집니다.
- 본문 안 줄바꿈은 `\` + `n` 두 글자로 이스케이프되어 **한 행이 유지**되고, `json.loads` 하면 실제 줄바꿈으로 복원됩니다.
- `inspect_line(line, number)`: JSON 객체인지 → `content`가 문자열인지 확인하고, 실패하면 `f"{number}행: {error}"`로 다시 올림.

| 사례 | 종류 | 메시지 |
| --- | --- | --- |
| `{"content": 123}` | 스키마 오류 (JSON으론 읽히지만 약속과 다름) | `2행: content는 문자열이어야 합니다` |
| 빈 줄 | 문법 오류 (JSON으로 못 읽음) | `3행: Expecting value: line 1 column 1 (char 0)` |

- 바깥 행 번호는 **파일의 위치**, JSON 파서 메시지 속 `line 1`은 **넘겨받은 한 줄 문자열 안의 위치**라 달라도 정상입니다.
- 실습 `load_jsonl(path)`: `for number, line in enumerate(stream, 1)` → `inspect_line(line, number)`. 저장 12행 = 로드 12개, 마지막 문서 `retention`(교육 자료 보관).

## 질문과 새로 알게 된 점

### 파이썬 문법에서 헷갈렸던 것

| 질문 | 핵심 |
| --- | --- |
| f-string `</{tag}>` | `{}`만 변수로 바뀌고 `<`, `/`, `>`는 그냥 글자 |
| `!r` | `repr`로 출력해서 따옴표, 공백, `\n`까지 보여 줌 |
| `split(". ")` | `"."`로 나누면 마지막이 빈 문자열이 되고 숫자 속 점에서도 잘려요 |
| `strip()` vs `split()` | `strip`은 양끝 공백 제거(문자열), `split`은 쪼개기(리스트) |
| `enumerate` 순서 vs 함수 인자 순서 | 꺼낼 때는 `(번호, 값)`, 넣을 때는 함수 정의 순서 `inspect_line(line, number)` |
| `HTMLParser` | 태그와 글자를 만날 때마다 메서드가 자동 호출. `in_p` 스위치가 켜졌을 때만 글자를 모음 |

### 실습 문제에서 한 실수

| 강의 | 실수 | 수정 |
| --- | --- | --- |
| 2-2 | `== "category"` (글자와 비교) | `== category` (변수와 비교) |
| 2-3 | `.split()` | `.strip()` |

### 개념 정리

| 질문 | 답 요약 |
| --- | --- |
| status를 고정하는 이유 (2-2) | 함수의 목적이 "현행 고르기"라서. 이력 비교가 필요하면 매개변수로 빼거나 조건을 제거하고, 버전 표시를 함께 넣음 |
| footer를 다르게 넘기면 (2-3) | 정확히 같은 줄만 제외돼요. 틀려도 에러가 없으니 `removed`로 확인 |
| `\n` 이스케이프 (2-4) | 줄바꿈이 `\` + `n` 두 글자로 저장돼서 한 행 유지. `loads`하면 복원 |
| 저장 후 다시 검수하는 이유 (2-4) | 쓰기 성공 ≠ 쓸 수 있는 구조. 문법 오류(JSON으로 못 읽음)와 스키마 오류(읽히지만 약속과 다름) |

### 2-Q4. JSONL 형식 (2-4)

옳은 설명은?

① 행과 행 사이에 쉼표를 넣는다  
② 사람이 읽기 좋게 `indent=2`로 저장한다  
③ 본문 안의 줄바꿈은 `\n`으로 이스케이프되어 한 행이 유지된다  
④ 파일 전체를 대괄호 `[ ]`로 감싼다

<details>
<summary>정답 보기</summary>

**③** — 한 줄에 JSON 객체 하나라 쉼표·대괄호는 쓰지 않고, `indent`를 쓰면 객체가 여러 줄로 나뉘어 형식이 깨져요.

### 2-Q5. 서술형 — 지울 것과 지킬 것 (2-3)

정제 단계에서 "지워도 되는 것"과 "절대 바꾸면 안 되는 것"을 예시와 함께 설명하세요.

<details>
<summary>예시 답안</summary>

- 지워도 되는 것: 연속 공백·탭, 빈 줄, 실제 문자열을 확인한 반복 하단 표기, 완전히 같은 문서의 복사본.
- 바꾸면 안 되는 것: 금액(12만원), 기간, 승인 시점(예약 전), 부정 표현(`자동 정산되지 않습니다`). 매끄럽게 고치다 `정산됩니다`가 되면 뜻이 반대가 되고, 하단이 반복된다고 숫자·날짜를 한꺼번에 지우면 본문 금액도 사라질 수 있어요.

</details>

### 2-Q6. 서술형 — 저장 후 다시 읽는 이유 (2-4)

JSONL을 저장한 뒤 다시 읽어 검수하는 이유와, 문법 오류·스키마 오류의 차이를 쓰세요.

<details>
<summary>예시 답안</summary>

쓰기에 성공했다고 다음 단계가 쓸 수 있는 구조라는 보장은 없어요. 다시 읽어서 문서 수와 필드·자료형을 확인해야 합니다. 문법 오류는 JSON으로 읽을 수 없는 경우(빈 줄), 스키마 오류는 읽히지만 약속한 구조가 아닌 경우(`content`가 숫자)예요. 행 번호를 붙여 보고하면 큰 파일에서도 고칠 곳을 바로 찾을 수 있고, 오류 행을 조용히 건너뛰면 안 됩니다.

</details>
